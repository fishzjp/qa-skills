# 任务：编写工单系统状态流转测试用例

你是测试工程师。请根据下方 PRD，为「客服工单系统」的核心状态流转编写测试用例文件（markmap 格式）。

被测系统为客服工作台（Web 页面，有 UI）。请直接输出最终用例文件的完整内容。

---

## 输入材料

### 材料 1：PRD《客服工单系统》状态机部分 v2.0

**工单状态**：待分配、处理中、待用户确认、已完成、已取消。

**状态流转规则**：

1. 工单创建后进入「待分配」
2. 待分配 →（客服接单）→ 处理中
3. 待分配 →（用户撤单）→ 已取消
4. 处理中 →（客服提交解决方案）→ 待用户确认
5. 处理中 →（客服转派）→ 待分配（工单回到池中，记录转派原因）
6. 待用户确认 →（用户确认解决）→ 已完成
7. 待用户确认 →（用户不认可，拒绝）→ 处理中（附拒绝理由）
8. 待用户确认 →（用户 72 小时未操作）→ 已完成（系统自动确认，视为认可）
9. 已完成 →（用户申诉，7 天内）→ 处理中（重新打开，需管理员审批）
10. 已取消 / 已完成（超 7 天）为终态，不可再变更

**并发与异常约束**：

- 同一工单同时只能有一个客服处于「处理中」的持有关系
- 用户撤单与客服接单并发时，以先到达者为准，后到操作失败并提示
- 转派时必须填写转派原因（必填）
- 拒绝时必须填写拒绝理由（必填）

**角色**：用户（创建/撤单/确认/拒绝/申诉）；客服（接单/提交方案/转派）；管理员（申诉审批）。
