# 积分商城兑换 测试用例

## 功能简介与角色

积分商城兑换功能：用户以积分兑换商品，每次兑换扣减相应积分；商品库存为 0 不可兑换，兑换成功库存减 1；兑换接口幂等，重复提交同一请求不重复扣分；每人每日限兑 3 次；积分次年 3 月 31 日统一清零。

| 角色 | 用它做什么 |
|------|-----------|
| 用户 | 浏览商品、使用积分兑换商品、查看兑换记录 |
| 测试组长 | 提供测试环境后台地址与测试账号 |

## 1. 兑换主流程

### 1.1 正常兑换

> 前置：用户已登录测试账号，积分余额 ≥ 1000；兑换页存在商品「便携充电宝」，积分价格为 500

- **TC-01-01 正常兑换商品成功，积分扣减正确** [P0]（SMOKE-1）
  - 操作步骤: 1. 打开 App -> 首页 -> 积分商城 -> 兑换页 2. 选择商品「便携充电宝」（积分价格 500）3. 点击「立即兑换」
  - 预期结果: 1. 页面显示兑换成功提示 2. 页面显示更新后的积分余额（原余额 - 500）

- **TC-01-02 兑换成功后商品库存减 1** [P1]
  - 前置条件: 商品「便携充电宝」当前库存为 5
  - 操作步骤: 1. 打开 App -> 首页 -> 积分商城 -> 兑换页 2. 记录商品「便携充电宝」当前显示库存（5）3. 兑换商品「便携充电宝」1 件 4. 刷新兑换页
  - 预期结果: 商品「便携充电宝」库存从 5 变为 4

### 1.2 兑换拦截

> 前置：用户已登录测试账号

- **TC-01-03 积分不足时兑换，被拦截** [P0]
  - 前置条件: 用户积分余额为 200；商品「便携充电宝」兑换价格为 500
  - 操作步骤: 1. 打开 App -> 首页 -> 积分商城 -> 兑换页 2. 选择商品「便携充电宝」3. 点击「立即兑换」
  - 预期结果: 1. 页面提示"积分不足" 2. 用户积分余额不变（仍为 200）

- **TC-01-04 库存为 0 时兑换，被拦截** [P1]
  - 前置条件: 商品「限量水杯」库存为 0；用户积分充足
  - 操作步骤: 1. 打开 App -> 首页 -> 积分商城 -> 兑换页 2. 选择商品「限量水杯」3. 点击「立即兑换」
  - 预期结果: 1. 页面提示"库存不足" 2. 用户积分余额不变

## 2. 兑换规则与限制

### 2.1 每日限兑

> 前置：用户已登录测试账号，积分余额充足；兑换页存在库存充足的商品

- **TC-02-01 每人每日限兑 3 次，第 4 次被拦截** [P0]
  - 前置条件: 用户当日已成功兑换 3 次
  - 操作步骤: 1. 打开 App -> 首页 -> 积分商城 -> 兑换页 2. 选择任一库存充足的商品 3. 点击「立即兑换」
  - 预期结果: 1. 页面提示"今日兑换次数已达上限" 2. 用户积分余额不变

- **TC-02-02 每日限兑次数自然日次日重置** [P1]
  - 前置条件: 用户当日已成功兑换 3 次（已达上限）
  - 操作步骤: 1. 确认当前兑换被拦截（提示"今日已达上限"）2. 将系统时间调整为次日 00:00:01（TODO：向开发确认测试环境时间调整方式）3. 打开 App -> 首页 -> 积分商城 -> 兑换页 4. 选择商品「便携充电宝」5. 点击「立即兑换」
  - 预期结果: 兑换成功，当日剩余可兑换次数恢复为 2 次

### 2.2 接口幂等

> 前置：用户已登录测试账号；积分余额为 1000；商品「便携充电宝」兑换价格为 500，库存 ≥ 2；用户当日已兑换 0 次

- **TC-02-03 同一幂等键重复提交不重复扣分** [P0]
  - 操作步骤（请开发执行）: 1. 使用同一幂等键 `exchange_key_001` 发起两次相同的兑换请求（兑换商品「便携充电宝」）2. 记录每次请求的响应
  - 预期结果（请开发反馈）: 1. 第一次请求返回兑换成功 2. 第二次请求返回重复请求提示或返回与第一次相同的成功结果 3. 用户积分仅扣减一次（余额 1000 - 500 = 500）
  - 验证方式: 开发查询积分余额表，确认用户积分余额为 500

- **TC-02-04 不同幂等键的请求各自独立扣分** [P1]
  - 操作步骤（请开发执行）: 1. 分别使用不同幂等键 `exchange_key_001` 和 `exchange_key_002` 发起两次兑换请求（兑换商品「便携充电宝」）2. 记录每次请求的响应
  - 预期结果（请开发反馈）: 1. 两次请求均返回兑换成功 2. 用户积分扣减两次（余额 1000 - 500 - 500 = 0）
  - 验证方式: 开发查询积分余额表，确认用户积分余额为 0

## 3. 兑换记录

> 前置：用户已登录测试账号，至少有 1 条成功兑换记录（如已兑换商品「便携充电宝」，扣减积分 500）

- **TC-03-01 兑换记录可在「我的-兑换记录」查看** [P1]
  - 操作步骤: 1. 打开 App -> 我的 -> 兑换记录
  - 预期结果: 1. 页面展示用户的兑换记录列表 2. 列表按兑换时间倒序排列（最新在最上方）

- **TC-03-02 兑换记录含商品名称、扣减积分、兑换时间** [P1]
  - 操作步骤: 1. 打开 App -> 我的 -> 兑换记录 2. 查看最近一条兑换记录
  - 预期结果: 1. 记录显示商品名称「便携充电宝」2. 记录显示扣减积分数值 500 3. 记录显示兑换时间（精确到分钟）

## 4. 失败恢复与逆向操作

- **TC-04-01 积分不足被拦截后，补充积分可正常兑换** [P1]
  - 前置条件: 用户积分余额为 200；商品「便携充电宝」兑换价格为 500
  - 操作步骤: 1. 兑换商品「便携充电宝」，被拦截提示"积分不足" 2. 为用户补充积分至 600（TODO：向开发确认测试环境积分补充方式）3. 再次兑换商品「便携充电宝」
  - 预期结果: 1. 第一次兑换被拦截，积分余额不变（200）2. 第二次兑换成功，积分扣减 500（余额 600 - 500 = 100）

- **TC-04-02 库存为 0 被拦截后，补货可正常兑换** [P2]
  - 前置条件: 商品「限量水杯」库存为 0；用户积分充足
  - 操作步骤: 1. 兑换商品「限量水杯」，被拦截提示"库存不足" 2. 后台补充商品「限量水杯」库存至 5（TODO：向测试组长确认后台补货路径）3. 再次兑换商品「限量水杯」
  - 预期结果: 1. 第一次兑换被拦截 2. 第二次兑换成功，库存减 1（5 -> 4）

## 5. 积分生命周期

- **TC-05-01 积分次年 3 月 31 日统一清零** [P1]
  - 前置条件: 用户当前积分余额 > 0（如 1000）
  - 操作步骤（请开发执行）: 1. 将系统日期设置为次年 3 月 31 日 2. 触发积分清零定时任务（TODO：向开发确认清零任务触发时点与执行方式）3. 查询用户积分余额与兑换记录
  - 预期结果（请开发反馈）: 1. 用户积分余额变为 0 2. 兑换记录中的历史记录仍可正常查看
  - 验证方式: 开发查询积分余额表确认余额为 0；查询兑换记录表确认历史记录保留
