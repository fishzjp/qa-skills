# 订单导出定时任务测试用例

## 功能性测试

### 正常导出流程
- **TC-FUNC-001**：前一日有「已完成」订单，定时任务触发后正确导出 CSV 文件
  - 前置条件：前一日存在已完成订单数据
  - 执行步骤：模拟定时任务在凌晨 2:00 触发
  - 预期结果：
    - CSV 文件生成，列顺序为：订单号、用户ID、金额（分）、完成时间
    - 文件上传至 `oss://reports/orders/orders_YYYYMMDD.csv`
    - 导出记录表新增一条记录，状态=成功，含文件路径、条数
    - 条数与实际导出行数一致

### 空数据导出
- **TC-FUNC-002**：前一日无「已完成」订单
  - 前置条件：前一日无任何已完成状态订单
  - 预期结果：
    - 仍生成 CSV 文件（仅表头，无数据行）
    - 文件上传至 OSS
    - 导出记录表新增记录，条数=0，状态=成功

### 导出范围验证
- **TC-FUNC-003**：仅导出状态变为「已完成」的订单，不含其他状态
  - 前置条件：前一日同时存在待支付、已发货、已完成等各状态订单
  - 预期结果：CSV 仅包含「已完成」状态订单

- **TC-FUNC-004**：边界——前一日 00:00:00 完成的订单应被包含
  - 前置条件：存在完成时间 = 前一日 00:00:00 的订单
  - 预期结果：该订单在导出文件中

- **TC-FUNC-005**：边界——前一日 23:59:59 完成的订单应被包含
  - 前置条件：存在完成时间 = 前一日 23:59:59 的订单
  - 预期结果：该订单在导出文件中

- **TC-FUNC-006**：边界——当日 00:00:00 完成的订单不应被包含
  - 前置条件：存在完成时间 = 执行日 00:00:00 的订单
  - 预期结果：该订单不在导出文件中

- **TC-FUNC-007**：前一日 23:59:59 之前完成但状态在前一日之后才变为完成的订单
  - 前置条件：订单完成时间在前一日范围，但状态变更时间可能跨日
  - 预期结果：以状态变为「已完成」的时间为准判断是否在范围内（待澄清：完成时间字段与状态变更时间的口径）

## CSV 格式测试

### 列与编码
- **TC-CSV-001**：CSV 表头正确性
  - 预期结果：表头为 `订单号,用户ID,金额,完成时间`（待澄清：是否有表头行）

- **TC-CSV-002**：UTF-8 编码验证
  - 预期结果：文件编码为 UTF-8，中文用户ID或特殊字符正确显示
  - 验证方式：检查 BOM 头、用 UTF-8 解码校验

- **TC-CSV-003**：金额单位为分
  - 前置条件：订单金额存在小数（如 12.34 元）
  - 预期结果：金额列输出 1234（分），无小数点

- **TC-CSV-004**：CSV 字段含逗号/引号/换行符的转义
  - 前置条件：用户ID或订单号中含特殊字符
  - 预期结果：按 CSV 标准正确转义（双引号包裹）

### 数据准确性
- **TC-CSV-005**：导出数据与数据库查询结果逐一比对
  - 预期结果：订单号、用户ID、金额、完成时间均一致

- **TC-CSV-006**：金额为 0 的订单正确导出
  - 预期结果：金额列显示 0

## 上传与记录测试

### OSS 上传
- **TC-UPLOAD-001**：文件成功上传至 `oss://reports/orders/` 路径
  - 预期结果：OSS 中可访问该文件，路径含正确日期

- **TC-UPLOAD-002**：文件名格式 `orders_YYYYMMDD.csv`
  - 预期结果：文件名日期与导出日期一致（如 orders_20260819.csv）

### 导出记录表
- **TC-RECORD-001**：成功导出后记录表新增一条
  - 预期结果：记录含文件路径、条数、状态=成功、执行时间

- **TC-RECORD-002**：记录中文件路径与实际上传路径一致
  - 预期结果：路径完全匹配

## 重试机制测试

### 步骤失败重试
- **TC-RETRY-001**：OSS 上传首次失败，重试后成功
  - 前置条件：模拟 OSS 首次超时，第二次正常
  - 预期结果：
    - 重试 1 次后成功
    - 导出记录状态=成功
    - 不触发告警

- **TC-RETRY-002**：数据库查询首次失败，重试后成功
  - 前置条件：模拟从库首次不可达，第二次恢复
  - 预期结果：重试后成功，状态=成功

- **TC-RETRY-003**：连续失败 3 次后终止，记录失败并告警
  - 前置条件：模拟 OSS 持续不可用
  - 预期结果：
    - 重试 3 次（间隔 5 分钟）后停止
    - 导出记录状态=失败
    - 触发告警通知

- **TC-RETRY-004**：重试间隔为 5 分钟
  - 预期结果：两次重试间时间差 ≈ 5 分钟

- **TC-RETRY-005**：CSV 生成阶段失败的重试
  - 前置条件：模拟磁盘满或写入异常
  - 预期结果：按重试逻辑执行，最终失败则记录+告警（待澄清：哪些步骤纳入重试范围）

## 幂等性测试

### 重复执行
- **TC-IDEMP-001**：同一天重复执行覆盖同名文件
  - 前置条件：当日已成功导出一次
  - 执行步骤：再次触发同一日期的导出
  - 预期结果：
    - OSS 中同名文件被覆盖
    - 导出记录表新增一条记录（不更新原有记录）

- **TC-IDEMP-002**：重复执行时前一日订单数据已变化
  - 前置条件：首次执行后，前一日又有订单变为已完成（如补单）
  - 预期结果：第二次导出包含新增的已完成订单，文件覆盖，记录新增

- **TC-IDEMP-003**：首次失败后重新执行成功
  - 前置条件：首次执行因 OSS 不可用失败
  - 预期结果：重新执行成功，生成新文件，记录新增一条成功记录

## 性能与数据量测试

### 大数据量
- **TC-PERF-001**：日常数据量 5 万行导出
  - 预期结果：任务在合理时间内完成（待澄清：SLA 时长要求），内存不溢出

- **TC-PERF-002**：大促数据量 500 万行导出
  - 预期结果：
    - CSV 文件成功生成并上传
    - 任务不因内存不足中断
    - 导出记录条数=500万

- **TC-PERF-003**：大文件 OSS 上传稳定性
  - 预期结果：500 万行文件上传不超时、不断点（待澄清：是否采用分片上传）

### 定时任务调度
- **TC-SCHED-001**：凌晨 2:00 准时触发
  - 预期结果：任务实际执行时间 ≈ 02:00:00 Asia/Shanghai

- **TC-SCHED-002**：服务器时区 Asia/Shanghai 确认
  - 前置条件：验证服务器时区设置
  - 预期结果：日期范围按 Asia/Shanghai 时区计算

- **TC-SCHED-003**：夏令时影响（Asia/Shanghai 无夏令时，但需确认时区配置）
  - 预期结果：不受夏令时影响

## 异常场景测试

- **TC-EXCEPT-002**：OSS 服务可用率 99.9% 边界（偶发失败）

- **TC-EXCEPT-003**：从库数据延迟（主从同步延迟）

  - 预期结果：CSV 中对应字段为空，不影响整体导出

- **TC-EXCEPT-005**：金额为负数或异常值
  - 预期结果：按实际值导出（待澄清：是否需要数据校验）

- **TC-EXCEPT-006**：完成时间为 NULL 的已完成订单
  - 预期结果：（待澄清：是否纳入导出范围）

### 并发与冲突
- **TC-EXCEPT-007**：两个定时任务实例同时执行
  - 预期结果：（待澄清：是否有分布式锁或单实例保障）

- **TC-EXCEPT-008**：手动重跑与定时任务同时触发
  - 预期结果：幂等覆盖，不产生数据损坏（待澄清：并发控制策略）

## 待澄清清单

1. 导出范围以「完成时间」字段还是「状态变更时间」字段为准？
2. CSV 文件是否包含表头行？
3. CSV 金额列是否需要对负数、异常金额做校验或过滤？
4. 完成时间为 NULL 的已完成订单是否纳入导出？
5. 重试机制覆盖哪些步骤（仅 OSS 上传？还是包含数据库查询、CSV 生成）？
6. 500 万行大文件 OSS 上传是否采用分片上传？上传超时阈值多少？
7. 导出任务 SLA 时长要求（5 万行 / 500 万行分别需在多久内完成）？
8. 从库主从延迟较大时，是否有延迟检查或降级策略？
9. 是否有分布式锁保障同一任务不被并发执行？
10. 手动重跑入口是否存在？触发方式是什么？
11. 告警通知的渠道和接收人是什么？
12. 导出记录表是否记录每次重试的明细，还是仅记录最终结果？
