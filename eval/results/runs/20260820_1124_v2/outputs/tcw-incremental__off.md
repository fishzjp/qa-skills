# 优惠券创建 测试用例

> **功能简介**：运营在管理后台创建优惠券模板，供 C 端用户领取。
>
> **角色**：运营 -> 创建/编辑/发布优惠券；运营组长 -> 创建/编辑/发布优惠券、手动提前结束；管理员 -> 手动提前结束。（[修改-v1.3]：运营组长新增提前结束权限）

**环境与账号** [修改-v1.3]：

| 项 | 值 |
|----|----|
| 管理后台入口 | TODO：向运维索取测试环境地址 |
| 运营测试账号 | TODO：向运营组长索取 |
| 运营组长测试账号 | TODO：向运营组长索取（[新增-v1.3]） |
| 管理员测试账号 | TODO：向运营组长索取 |

**术语表**：券模板=优惠券的定义记录；门槛=订单需达到的金额；每人限领=同一用户可领取该券的最大张数（[新增-v1.3]）。

**图例**：P0=冒烟 / P1=常规（默认）/ P2=边界低频。

**变更标记说明**：`[新增-v1.3]` = v1.3 新增；`[修改-v1.3]` = v1.3 修改；`[删除-v1.3]` = v1.3 删除。未标记的用例/段落为 v1.3 未变更内容。

## 1. 创建优惠券

> 前置：运营账号已登录管理后台，进入「营销中台 -> 券工场 -> 新建券」

- **TC-01-01 正常创建满减券** [P0]（SMOKE-1） [修改-v1.3]
  - 操作步骤: 1. 填写券名称"周年庆满100减20" 2. 面额填 20 3. 门槛填 100 4. 有效期选固定时间段（明天至后30天）5. 发放总量 1000 6. 每人限领填 1（[新增-v1.3]）7. 点击提交
  - 预期结果: 创建成功，列表出现该券，状态为待发布

- **TC-01-02 面额边界值校验** [P2] [修改-v1.3]
  - 操作步骤: 1. 面额分别填写 0、1、500、501 提交（其余字段含每人限领填合法值）
  - 预期结果: 0 与 501 提示"面额需为 1-500 的整数"被拦截；1 与 500 创建成功

- **TC-01-03 门槛小于面额拦截** [P1]
  - 操作步骤: 1. 面额填 20，门槛填 10，其余合法，提交
  - 预期结果: 提示"使用门槛不能低于面额"，提交被拦截

- **TC-01-04 券名称重复拦截** [P1]
  - 前置条件: 已存在券"周年庆满100减20"
  - 操作步骤: 1. 新建券，名称填"周年庆满100减20"，其余合法，提交
  - 预期结果: 提示"名称已存在"，创建被拦截

- **TC-01-05 每人限领边界值校验** [P2] [新增-v1.3]
  - 操作步骤: 1. 每人限领分别填写 0、1、10、11 提交（其余字段填合法值）
  - 预期结果: 0 与 11 提示"每人限领需为 1-10 的整数"被拦截；1 与 10 创建成功

- **TC-01-06 发放总量上限校验** [P2] [新增-v1.3]
  - 操作步骤: 1. 发放总量分别填写 0、1、50000、50001 提交（其余字段填合法值）
  - 预期结果: 0 与 50001 提示"发放总量需为 1-50000 的整数"被拦截；1 与 50000 创建成功

## 2. 发布与状态

> 前置：已存在一张待发布状态的券

- **TC-02-01 发布优惠券** [P0]（SMOKE-2）
  - 操作步骤: 1. 在券列表对待发布券点击「发布」
  - 预期结果: 券状态变为已发布，C 端可见可领

- **TC-02-02 到期自动结束** [P1]
  - 操作步骤: 1. 将一张已发布券的结束时间改为 2 分钟后（用编辑发放总量外的字段需待发布态，故创建时设短有效期）2. 等待到期
  - 预期结果: 到期后 1 小时内状态自动变为已结束，超过 1 小时未变判失败

- **TC-02-03 手动提前结束（管理员/运营组长）** [P1] [修改-v1.3]
  - 前置条件: 已存在两张已发布状态的券（分别用于管理员和运营组长操作）
  - 操作步骤: 1. 管理员账号登录，对已发布券 A 点击「提前结束」2. 换运营组长账号登录，对已发布券 B 点击「提前结束」
  - 预期结果: 两次操作后券 A、券 B 状态均变为已结束，C 端不可再领取

- **TC-02-04 普通运营无提前结束权限** [P1] [新增-v1.3]
  - 前置条件: 已存在一张已发布状态的券
  - 操作步骤: 1. 普通运营账号登录，进入券列表，查看已发布券操作栏
  - 预期结果: 已发布券无「提前结束」操作入口（或点击时提示无权限），券状态不变

### 待澄清

1. **提示文案确认**：TC-01-02、TC-01-05、TC-01-06 中的拦截提示文案（如"面额需为 1-500 的整数""每人限领需为 1-10 的整数""发放总量需为 1-50000 的整数"）为推测值，需与开发/产品确认实际文案。
2. **无权限交互形式**：TC-02-04 中普通运营无提前结束权限的具体表现（隐藏按钮 vs 置灰 vs 点击提示无权限）需与产品确认。
3. **每人限领默认值验证**：需求提到默认值 1，是否需要单独增加一条用例验证新建页面打开时该字段默认显示 1，还是并入 TC-01-01 中隐含覆盖即可，待与产品确认。
4. **存量券兼容性**：面额上限下调和发放总量上限下调后，历史已创建但未结束的券是否受影响（如面额 600 的存量券是否仍可正常领取/核销），是否需要补充回归测试，待与产品/开发确认。
5. **运营组长角色范围**：运营组长除提前结束外是否拥有其他运营全部操作权限（创建/编辑/发布），当前用例假设运营组长具备基础运营操作能力，待与产品确认。
