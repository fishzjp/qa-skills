# 客服工单系统 状态流转测试用例

## 导读

### 功能简介 + 角色表

客服工单系统支持工单从创建到完成的全生命周期状态流转，涉及用户、客服、管理员三种角色的协作。核心状态包括：待分配、处理中、待用户确认、已完成、已取消。

| 角色 | 可用操作 |
|------|---------|
| 用户 | 创建工单、撤单、确认解决、拒绝解决方案、申诉 |
| 客服 | 接单、提交解决方案、转派 |
| 管理员 | 申诉审批 |

### 术语表

| 术语 | 中文名 | 解释 |
|------|--------|------|
| 待分配 | 待分配状态 | 工单已创建但尚未有客服接单，在工单池中等待 |
| 处理中 | 处理中状态 | 客服已接单正在处理 |
| 待用户确认 | 待用户确认状态 | 客服已提交解决方案，等待用户确认 |
| 已完成 | 已完成状态 | 工单处理完毕，7天内可申诉，超7天为终态 |
| 已取消 | 已取消状态 | 用户主动撤单，终态不可变更 |
| 转派 | 转派操作 | 客服将工单退回工单池，由其他客服接单 |
| 撤单 | 撤单操作 | 用户主动取消工单 |
| 申诉 | 申诉操作 | 工单完成后用户对结果不满意，7天内申请重新打开 |
| 终态 | 终态 | 不可再变更的状态（已取消、已完成超7天） |

## 1. 待分配状态

> 共享前置：已登录对应角色的工作台；存在处于「待分配」状态的工单

### 1.1 工单创建进入待分配

- **TC-01-01 工单创建后进入待分配状态** [P0]（SMOKE-1）
  - 前置条件: 以用户 user001 登录用户工作台（后台 → 用户工作台 → 我的工单）
  - 操作步骤: 1. 进入「我的工单」页面 2. 点击「创建工单」按钮 3. 填写工单标题"测试工单-流转001"，工单描述"用于测试状态流转主线" 4. 点击「提交」
  - 预期结果: 页面提示创建成功；工单列表中出现新工单，状态列显示「待分配」

- **TC-01-02 待分配工单在客服工单池中可见** [P1]
  - 前置条件: 以客服 agent001 登录客服工作台（后台 → 客服工作台 → 工单列表）
  - 操作步骤: 1. 进入工单列表页面 2. 查找工单 WO-20240115-001
  - 预期结果: 工单 WO-20240115-001 在列表中可见，状态显示「待分配」，行内有「接单」按钮可点击

### 1.2 客服接单（待分配 → 处理中）

- **TC-01-03 客服接单成功，工单从待分配变为处理中** [P0]（SMOKE-2）
  - 前置条件: 以客服 agent001 登录客服工作台
  - 操作步骤: 1. 进入工单列表（后台 → 客服工作台 → 工单列表）2. 找到状态为「待分配」的工单 WO-20240115-001 3. 点击「接单」按钮
  - 预期结果: 页面提示接单成功；工单状态从「待分配」变为「处理中」；工单详情中持有人显示为 agent001

- **TC-01-04 接单后工单详情页显示处理中状态及操作按钮** [P1]
  - 前置条件: 工单 WO-20240115-001 已被 agent001 接单，状态为「处理中」
  - 操作步骤: 1. 在工单列表点击工单标题进入工单详情页 2. 查看状态标签、持有人信息及可用操作按钮
  - 预期结果: 状态标签显示「处理中」；持有人显示 agent001；详情页出现「提交解决方案」和「转派」按钮

### 1.3 用户撤单（待分配 → 已取消）

- **TC-01-05 用户撤单成功，工单从待分配变为已取消** [P1]
  - 前置条件: 以用户 user001 登录用户工作台，工单 WO-20240115-002 状态为「待分配」
  - 操作步骤: 1. 进入「我的工单」页面（后台 → 用户工作台 → 我的工单）2. 找到工单 WO-20240115-002 3. 点击「撤单」按钮 4. 在确认弹窗中点击「确认」
  - 预期结果: 页面提示撤单成功；工单状态从「待分配」变为「已取消」；工单列表中该工单状态列显示「已取消」

- **TC-01-06 撤单后客服工单池中该工单不再显示为待分配** [P1]
  - 前置条件: 工单 WO-20240115-002 已被用户撤单
  - 操作步骤: 1. 以客服 agent001 登录客服工作台 2. 进入工单列表 3. 查找工单 WO-20240115-002
  - 预期结果: 工单池中 WO-20240115-002 不再显示为「待分配」状态（列表中不出现或状态已变为「已取消」且无「接单」按钮）

### 1.4 非法转换拦截

- **TC-01-07 待分配状态下用户无法直接确认解决** [P2]

  - 预期结果: 工单详情页不显示「确认解决」按钮（或按钮不可点击），无法从待分配直接跳到已完成

  - 预期结果: 工单状态显示「待用户确认」；详情页显示客服提交的解决方案内容"已为用户重置密码，请查收短信"；出现「确认解决」和「拒绝」按钮

### 2.2 客服转派（处理中 → 待分配）

> 共享前置：以客服 agent001 登录，工单 WO-20240115-005 已被 agent001 接单，状态为「处理中」

- **TC-02-03 客服填写转派原因后转派成功，工单回到待分配** [P1]

  - 预期结果: 页面提示转派成功；工单状态从「处理中」变为「待分配」；工单详情中显示转派原因"该工单涉及支付系统问题，需支付组客服处理"

- **TC-02-04 转派原因未填写时提交被拦截** [P1]

  - 预期结果: 提交被拦截；提示"转派原因不能为空"（或类似文案）；工单状态保持「处理中」不变；表单数据不丢失

- **TC-02-05 转派原因仅输入空格时提交被拦截** [P2]

  - 预期结果: 提交被拦截；提示转派原因不能为空；工单状态保持「处理中」不变

- **TC-02-06 转派原因填写超长文本时提交** [P2]
  - 操作步骤: 1. 打开工单 WO-20240115-005 详情 2. 点击「转派」按钮 3. 转派原因输入框填写500字以上文本 4. 点击「确认转派」
  - 预期结果: 转派成功或提示超出长度限制（以系统实际限制为准；转派原因最大长度需向产品确认，见待澄清清单）

- **TC-02-07 转派后工单在工单池中重新可见为待分配** [P1]
  - 前置条件: 工单 WO-20240115-005 已被转派，状态为「待分配」

- **TC-02-08 转派后原客服不再持有该工单** [P1]

  - 操作步骤: 1. 以客服 agent001 登录客服工作台 2. 进入「我的处理中工单」列表 3. 查找工单 WO-20240115-005
