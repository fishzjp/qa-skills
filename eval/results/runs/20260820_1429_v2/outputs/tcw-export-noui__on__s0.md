# 订单导出定时任务 测试用例

## 导读

### 功能简介与角色表

每日凌晨 2:00 将前一日所有「已完成」状态的订单导出为 CSV 文件，上传至对象存储 `oss://reports/orders/`，并在导出记录表中登记一条记录（含文件路径、条数、状态）。

| 角色 | 职责 |
|------|------|
| 测试工程师 | 设计用例、整合交付、分析反馈结果 |
| 后端开发 | 代为执行后端测试操作（触发任务、查库、查日志、下载文件），反馈实际结果 |
| 运维 | 提供环境配置、监控大盘、告警通道配置 |

> ⚠️ 本功能为后端定时任务，无任何用户界面。所有用例采用**测试-开发协作模式**：操作步骤由开发执行，预期结果由开发反馈，验证方式为开发查库/查日志/查对象存储。

### 术语表

| 术语 | 含义 |
|------|------|
| 已完成 | 订单的终态状态，表示订单已完成全部业务流程 |
| 前一自然日 | 服务器时区（Asia/Shanghai）前一天的 00:00:00 至 23:59:59 |
| 对象存储 | 用于存储导出 CSV 文件的服务，路径前缀 `oss://reports/orders/` |
| 导出记录表 | 记录每次导出操作结果的数据表，含文件路径、条数、状态等字段 |
| 从库 | 订单数据库的只读副本，导出任务的数据来源 |
| 数据日期 | 导出文件对应的业务日期（前一日），非任务执行日期 |
| 重跑 | 对同一数据日期重复执行导出任务 |

## 待澄清问题

以下问题在编写过程中发现，需向后端开发或产品经理确认后补充/调整对应用例：

1. **CSV 文件是否包含表头行**：若包含，表头名称是什么（如"订单号,用户ID,金额,完成时间"）？影响 TC-02-05、TC-04-02 中行数统计的预期值。

3. **CSV 文件是否带 UTF-8 BOM**：影响 TC-02-02 编码验证的判定标准。
4. **重试时是从整个任务第一步重新开始，还是从失败的步骤继续**：影响 TC-05-04、TC-05-05 的预期行为描述。
5. **如果数据库不可用导致无法写入失败记录**：是否有本地日志兜底？影响 TC-04-03、TC-08-01 的预期。
6. **告警的具体方式和接收人**：邮件/短信/IM？接收人是谁？影响 TC-05-06、TC-05-07 的验证方式。
7. **导出记录表的表名和完整字段定义**：设计文档仅提到"含文件路径、条数、状态"，是否有其他字段（如执行时间、执行人、重试次数等）？影响 TC-04-01 的验证范围。
8. **大促 500 万行导出是否有总超时限制**：同步执行还是异步执行？影响 TC-07-02 的预期完成时间判定。
9. **对象存储上传失败后，本地临时 CSV 文件是否清理**：清理时机是什么？影响是否需要补充临时文件清理的用例。
10. **从库同步延迟是否有检查机制**：如延迟超过阈值时跳过导出或告警？影响 TC-08-03 的预期行为。
11. **任务执行超时（跨日）时是否有并发控制/锁机制**：防止同一任务重复触发？影响 TC-08-04 的预期。
12. **"状态变为已完成"的判定字段**：是按订单状态变更时间还是订单最后更新时间？影响 TC-01-03 至 TC-01-06 的数据准备。
13. **对象存储文件的访问权限/生命周期策略**：导出文件是否有过期自动删除？是否需要补充文件保留期验证用例？
14. **导出记录表是否对同一日期允许多条记录**：设计文档说"新增一条"暗示允许，需确认无唯一约束。影响 TC-04-04、TC-06-02。
15. **大促场景 CSV 文件大小可能很大**：对象存储是否有单文件大小限制？是否需要分片上传？影响 TC-07-02 的预期。
