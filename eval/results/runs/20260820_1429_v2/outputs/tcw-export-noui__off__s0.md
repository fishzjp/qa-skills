# 订单导出定时任务测试用例

## 1. 正向功能测试
### 1.1 定时任务触发
- 验证系统时间到达凌晨 2:00 (Asia/Shanghai) 时任务是否自动触发
- 验证任务执行前依赖的订单库只读从库及对象存储服务连接正常
### 1.2 数据提取范围验证
- 验证仅导出前一自然日 00:00:00 - 23:59:59 (Asia/Shanghai) 内的订单
- 验证仅导出状态为「已完成」的订单，排除其他状态订单
- 验证在 00:00:00 和 23:59:59 临界时间点变为「已完成」的订单是否被正确包含/排除
- 验证历史已「已完成」但完成时间不在前一自然日内的订单不被导出
### 1.3 CSV 文件生成与内容验证
- 验证文件名格式是否为 `orders_YYYYMMDD.csv` (如 orders_20260819.csv)
- 验证文件上传路径是否为 `oss://reports/orders/`
- 验证 CSV 文件编码为 UTF-8
- 验证 CSV 表头列名及顺序为：订单号、用户ID、金额（分）、完成时间
- 验证「金额」字段是否以分为单位展示，无小数点
- 验证「完成时间」字段格式是否符合预期统一定义（如标准时间戳或 ISO8601 格式）
- 验证 CSV 字段分隔符、换行符是否符合规范（如逗号分隔，\n 或 \r\n 换行）
### 1.4 导出记录登记验证
- 验证任务成功执行后，导出记录表中新增一条记录
- 验证记录中的「文件路径」正确指向 `oss://reports/orders/orders_YYYYMMDD.csv`
- 验证记录中的「条数」与实际导出的 CSV 文件数据行数一致
- 验证记录中的「状态」字段值为「成功」

## 2. 异常与重试机制测试
### 2.1 数据库异常
- 模拟订单库只读从库连接超时或断开，验证任务是否进入重试
- 验证重试次数是否最多为 3 次
- 验证重试间隔是否为 5 分钟
- 验证 3 次重试后仍失败时，导出记录表中新增「状态=失败」的记录
- 验证 3 次重试失败后是否成功触发告警
### 2.2 对象存储 (OSS) 异常
- 模拟 OSS 上传接口超时或返回 5xx 错误，验证任务是否进入重试机制
- 验证 OSS 上传成功但写数据库记录失败时的重试行为与状态流转
- 模拟 OSS 可用性下降（如 99.9% 以下），验证文件上传的容错与重试
### 2.3 告警机制验证
- 验证告警通知渠道是否通畅（邮件/短信/IM 工具等）
- 验证告警内容是否包含失败日期、失败原因等关键信息

## 3. 幂等性与重跑测试
### 3.1 任务重跑覆盖
- 手动触发同一天的任务重跑，验证 OSS 中同名文件 (`orders_YYYYMMDD.csv`) 被新文件覆盖
- 验证重跑后生成的 CSV 文件内容是否为最新的全量前一日「已完成」订单
- 验证重跑不会报错，且导出记录表中新增一条记录（状态为成功）
### 3.2 部分失败后重跑
- 验证首次任务因 OSS 失败终止后，重跑该日任务能否正常生成并覆盖文件
- 验证多次重跑是否会生成多条导出记录，且历史失败记录保留不丢失

## 4. 性能与容量测试
### 4.1 日常数据量验证
- 模拟前一日 5 万行已完成订单，验证任务执行耗时是否在可接受范围内
- 验证 5 万行数据导出时内存占用稳定，无内存溢出 (OOM)
### 4.2 大促数据量验证
- 模拟前一日 500 万行已完成订单，验证任务是否能够成功执行
- 验证大促数据量下的任务执行耗时及数据库读取是否引发慢查询
- 验证大促数据量生成的 CSV 文件大小是否符合 OSS 上传限制及系统处理能力
- 验证大文件上传 OSS 是否支持分片上传或断点续传，及超时处理
### 4.3 资源监控
- 监控任务执行期间服务器的 CPU、内存、网络 IO 及数据库连接池使用率

## 5. 边界与兼容性测试
### 5.1 空数据场景
- 验证前一日无「已完成」订单时，任务是否能正常执行
- 验证空数据场景下是否生成只有表头的 CSV 文件并上传至 OSS
- 验证空数据场景下导出记录表是否正常新增「条数=0，状态=成功」的记录
### 5.2 特殊字符场景
- 验证订单数据中包含逗号、双引号、换行符等特殊字符时，CSV 字段是否能正确转义
- 验证用户ID或金额字段包含异常字符时的容错处理
### 5.3 时区与跨时区场景
- 验证服务器时区设置为 Asia/Shanghai 时，跨时区订单（如 UTC 时间下的订单）的时间范围计算是否正确
- 验证夏令时/冬令时切换期间（如存在相关时区配置时），任务触发与时间范围计算不受影响
### 5.4 日期边界场景
- 验证月末执行时，能否正确获取上月最后一天的数据
- 验证闰年 2 月 29 日的数据范围计算是否正确
- 验证跨年执行（如 2026-01-01 凌晨执行导出 2025-12-31 数据）是否正常

## 6. 待澄清清单
- [ ] 「完成时间」在 CSV 中的具体格式要求未明确（时间戳、yyyy-MM-dd HH:mm:ss 等）？
- [ ] 告警触发的方式及接收人未明确（邮件、短信、内部 IM 平台等）？
- [ ] 空数据时是否需要生成空 CSV 文件，还是跳过上传只记录状态为成功？
- [ ] 重跑任务时的触发方式未明确（通过 API 接口、手动更改定时任务配置、后台管理界面等）？
- [ ] 金额（分）是否存在负数场景（如退款单是否也属于已完成状态被导出）？
- [ ] OSS 上传大文件是否有大小限制，是否需强制采用分片上传机制？
