# 客服工单系统 - 状态流转测试用例

## 1. 工单创建与初始状态

### TC-001: 用户创建工单后初始状态为「待分配」
- **优先级**: P0
- **前置条件**: 用户已登录客服工作台（Web）
- **操作步骤**:
  1. 进入工单创建页面，填写工单标题、描述等必要信息
  2. 点击提交创建工单
  3. 查看工单详情页状态字段
- **预期结果**:
  - 工单创建成功，提示创建成功
  - 工单状态显示为「待分配」
  - 工单出现在待分配工单池中，可被客服查看

## 2. 待分配状态流转

### TC-002: 客服接单 — 待分配 → 处理中（正常流程）
- **优先级**: P0
- **前置条件**: 存在一条状态为「待分配」的工单；客服已登录工作台
- **操作步骤**:
  1. 客服进入待分配工单列表
  2. 选择目标工单，点击「接单」按钮
- **预期结果**:
  - 工单状态变更为「处理中」
  - 当前持有客服字段显示为该客服
  - 工单从待分配池中移除

### TC-003: 用户撤单 — 待分配 → 已取消（正常流程）
- **优先级**: P0
- **前置条件**: 存在一条状态为「待分配」的工单；用户已登录
- **操作步骤**:
  1. 用户进入工单详情页
  2. 点击「撤单」按钮
  3. 确认撤单操作
- **预期结果**:
  - 工单状态变更为「已取消」
  - 工单从待分配池中移除

## 3. 处理中状态流转

### TC-004: 客服提交解决方案 — 处理中 → 待用户确认（正常流程）
- **优先级**: P0
- **前置条件**: 存在一条状态为「处理中」的工单；客服已登录且为当前持有客服
- **操作步骤**:
  1. 客服进入工单处理页面
  2. 填写解决方案内容
  3. 点击「提交解决方案」
- **预期结果**:
  - 工单状态变更为「待用户确认」
  - 用户侧可查看解决方案内容
  - 开始计算 72 小时自动确认倒计时

### TC-005: 客服转派 — 处理中 → 待分配（正常流程，填写转派原因）
- **优先级**: P0
- **前置条件**: 存在一条状态为「处理中」的工单；客服已登录且为当前持有客服
- **操作步骤**:
  1. 客服进入工单处理页面
  2. 点击「转派」按钮
  3. 在弹窗中填写转派原因
  4. 确认转派
- **预期结果**:
  - 工单状态变更为「待分配」
  - 工单回到待分配池中
  - 转派原因被记录，可在工单操作日志中查看
  - 原客服不再持有该工单

### TC-006: 客服转派 — 未填写转派原因应拦截
- **优先级**: P1
- **前置条件**: 存在一条状态为「处理中」的工单；客服已登录且为当前持有客服
- **操作步骤**:
  1. 客服进入工单处理页面
  2. 点击「转派」按钮
  3. 转派原因留空，点击确认转派
- **预期结果**:
  - 转派操作失败，提示「转派原因为必填项」
  - 工单状态仍为「处理中」
  - 工单未被移回待分配池

### TC-007: 转派后工单可被其他客服重新接单
- **优先级**: P1
- **前置条件**: 工单已被客服 A 转派，状态为「待分配」
- **操作步骤**:
  1. 客服 B 在待分配池中查看该工单
  2. 客服 B 点击「接单」
- **预期结果**:
  - 工单状态变更为「处理中」
  - 当前持有客服显示为客服 B
  - 工单操作日志中可查看转派记录及原客服 A

## 4. 待用户确认状态流转

### TC-008: 用户确认解决 — 待用户确认 → 已完成（正常流程）
- **优先级**: P0
- **前置条件**: 存在一条状态为「待用户确认」的工单；用户已登录
- **操作步骤**:
  1. 用户进入工单详情页
  2. 查看客服提交的解决方案
  3. 点击「确认解决」按钮
- **预期结果**:
  - 工单状态变更为「已完成」
  - 完成时间记录为当前时间，用于 7 天申诉窗口计算

### TC-009: 用户拒绝 — 待用户确认 → 处理中（正常流程，填写拒绝理由）
- **优先级**: P0
- **前置条件**: 存在一条状态为「待用户确认」的工单；用户已登录
- **操作步骤**:
  1. 用户进入工单详情页
  2. 查看客服提交的解决方案
  3. 点击「不认可/拒绝」按钮
  4. 填写拒绝理由
  5. 确认提交
- **预期结果**:
  - 工单状态变更为「处理中」
  - 拒绝理由被记录，客服可在工单中查看
  - 客服可继续处理该工单

### TC-010: 用户拒绝 — 未填写拒绝理由应拦截
- **优先级**: P1
- **前置条件**: 存在一条状态为「待用户确认」的工单；用户已登录
- **操作步骤**:
  1. 用户进入工单详情页
  2. 点击「不认可/拒绝」按钮
  3. 拒绝理由留空，点击确认提交
- **预期结果**:
  - 拒绝操作失败，提示「拒绝理由为必填项」
  - 工单状态仍为「待用户确认」

### TC-011: 72 小时未操作 — 系统自动确认 → 已完成
- **优先级**: P0
- **前置条件**: 存在一条状态为「待用户确认」的工单；用户在 72 小时内未进行任何操作
- **操作步骤**:
  1. 模拟等待超过 72 小时（或触发系统定时任务）
  2. 检查工单状态及操作日志
- **预期结果**:
  - 工单状态自动变更为「已完成」
  - 操作日志标记为「系统自动确认，视为用户认可」
  - 完成时间记录为自动确认时间

### TC-012: 71 小时 59 分未操作 — 不触发自动确认
- **优先级**: P1
- **前置条件**: 存在一条状态为「待用户确认」的工单
- **操作步骤**:
  1. 模拟等待 71 小时 59 分（未满 72 小时）
  2. 检查工单状态
- **预期结果**:
  - 工单状态仍为「待用户确认」
  - 自动确认未触发

### TC-013: 72 小时内用户操作 — 不触发自动确认
- **优先级**: P1
- **前置条件**: 存在一条状态为「待用户确认」的工单
- **操作步骤**:
  1. 在 72 小时内用户执行确认或拒绝操作
  2. 等待超过 72 小时后检查工单状态
- **预期结果**:
  - 按 TC-008 / TC-009 规则正常流转
  - 系统不执行自动确认

## 5. 已完成状态流转

### TC-014: 用户申诉（7 天内，审批通过）— 已完成 → 处理中
- **优先级**: P0
- **前置条件**: 存在一条状态为「已完成」的工单，完成时间在 7 天内；用户与管理员均已登录
- **操作步骤**:
  1. 用户进入工单详情页，点击「申诉」
  2. 管理员在审批列表中查看该申诉
  3. 管理员审批通过
- **预期结果**:
  - 工单状态变更为「处理中」，工单重新打开
  - 操作日志记录申诉及管理员审批信息

### TC-015: 用户申诉（7 天内，审批拒绝）— 已完成不变
- **优先级**: P1
- **前置条件**: 存在一条状态为「已完成」的工单，完成时间在 7 天内
- **操作步骤**:
  1. 用户进入工单详情页，点击「申诉」
  2. 管理员审批拒绝
- **预期结果**:
  - 工单状态仍为「已完成」
  - 操作日志记录申诉及管理员拒绝信息

### TC-016: 用户申诉（恰好第 7 天）— 允许申诉
- **优先级**: P1
- **前置条件**: 存在一条状态为「已完成」的工单，完成时间恰好为第 7 天（边界值）
- **操作步骤**:
  1. 用户进入工单详情页
  2. 点击「申诉」
- **预期结果**:
  - 申诉入口可用，申诉操作可提交
  - 工单进入待审批状态

### TC-017: 用户申诉（超过 7 天）— 申诉入口不可用
- **优先级**: P0
- **前置条件**: 存在一条状态为「已完成」的工单，完成时间超过 7 天
- **操作步骤**:
  1. 用户进入工单详情页
  2. 检查申诉入口
- **预期结果**:
  - 申诉按钮不可见或置灰不可点击
  - 提示「已超过 7 天申诉期限」
  - 工单状态仍为「已完成」

## 8. 并发与异常约束

### TC-023: 同一工单同时只能有一个客服持有处理中
- **优先级**: P0
- **前置条件**: 存在一条状态为「待分配」的工单；客服 A 与客服 B 均已登录
- **操作步骤**:
  1. 客服 A 与客服 B 同时对同一工单点击「接单」
- **预期结果**:
  - 仅一方接单成功，工单状态变更为「处理中」，持有客服为成功方
  - 另一方接单失败，提示「工单已被其他客服接单」
  - 同一时刻不存在两个客服同时持有处理中关系

### TC-024: 用户撤单与客服接单并发 — 撤单先到
- **优先级**: P0
- **前置条件**: 存在一条状态为「待分配」的工单；用户与客服均已登录
- **操作步骤**:
  1. 用户点击「撤单」（操作先到达服务端）
  2. 客服几乎同时点击「接单」（操作后到达服务端）
- **预期结果**:
  - 用户撤单成功，工单状态为「已取消」
  - 客服接单失败，提示「工单已被取消」
  - 工单状态最终为「已取消」

### TC-025: 用户撤单与客服接单并发 — 接单先到
- **优先级**: P0
- **前置条件**: 存在一条状态为「待分配」的工单；用户与客服均已登录
- **操作步骤**:
  1. 客服点击「接单」（操作先到达服务端）
  2. 用户几乎同时点击「撤单」（操作后到达服务端）
- **预期结果**:
  - 客服接单成功，工单状态为「处理中」
  - 用户撤单失败，提示「工单已被客服接单，无法撤单」
  - 工单状态最终为「处理中」

## 9. 角色权限校验

### TC-026: 用户无权执行客服操作（接单 / 提交方案 / 转派）
- **优先级**: P1
- **前置条件**: 用户已登录；存在待分配和处理中工单
- **操作步骤**:
  1. 用户查看待分配工单详情，检查是否有「接单」入口
  2. 用户查看处理中工单详情，检查是否有「提交方案」「转派」入口
  3. 尝试通过 URL 直接访问客服操作接口
- **预期结果**:
  - 页面上不展示客服操作按钮
  - 接口层面鉴权拒绝，返回无权限提示

### TC-027: 客服无权执行用户操作（撤单 / 确认 / 拒绝 / 申诉）
- **优先级**: P1
- **前置条件**: 客服已登录；存在待分配、待用户确认、已完成工单
- **操作步骤**:
  1. 客服查看待分配工单详情，检查是否有「撤单」入口
  2. 客服查看待用户确认工单详情，检查是否有「确认解决」「拒绝」入口
  3. 客服查看已完成工单详情，检查是否有「申诉」入口
  4. 尝试通过 URL 直接访问用户操作接口
- **预期结果**:
  - 页面上不展示用户操作按钮
  - 接口层面鉴权拒绝，返回无权限提示

### TC-028: 管理员申诉审批权限校验
- **优先级**: P1
- **前置条件**: 存在用户已提交的申诉工单；管理员与普通客服均已登录
- **操作步骤**:
  1. 管理员查看审批列表，检查是否可见申诉工单
  2. 管理员执行审批通过 / 拒绝
  3. 普通客服尝试访问审批列表或执行审批操作
- **预期结果**:
  - 管理员可查看并执行审批操作
  - 普通客服不可见审批入口，接口鉴权拒绝

## 10. 边界与补充场景

### TC-029: 工单经历完整生命周期闭环（创建→接单→提交→确认→申诉→重开→提交→自动确认）
- **优先级**: P1
- **前置条件**: 用户、客服、管理员账号均可用
- **操作步骤**:
  1. 用户创建工单（待分配）
  2. 客服接单（处理中）
  3. 客服提交解决方案（待用户确认）
  4. 用户确认解决（已完成）
  5. 用户 7 天内申诉，管理员审批通过（处理中）
  6. 客服重新提交解决方案（待用户确认）
  7. 用户 72 小时未操作（已完成）
- **预期结果**:
  - 每一步状态流转均正确
  - 操作日志完整记录全过程

### TC-030: 工单经历转派循环（接单→转派→重新接单→提交方案）
- **优先级**: P1
- **前置条件**: 存在待分配工单；客服 A 与客服 B 均已登录
- **操作步骤**:
  1. 客服 A 接单（处理中）
  2. 客服 A 填写转派原因并转派（待分配）
  3. 客服 B 接单（处理中）
  4. 客服 B 提交解决方案（待用户确认）
- **预期结果**:
  - 每一步状态流转正确
  - 转派原因及两次接单记录均在操作日志中可查

### TC-031: 工单经历拒绝循环（提交→拒绝→重新提交→确认）
- **优先级**: P1
- **前置条件**: 存在处理中工单；客服与用户均已登录
- **操作步骤**:
  1. 客服提交解决方案（待用户确认）
  2. 用户填写拒绝理由并拒绝（处理中）
  3. 客服查看拒绝理由后重新提交解决方案（待用户确认）
  4. 用户确认解决（已完成）
- **预期结果**:
  - 每一步状态流转正确
  - 拒绝理由及两次解决方案均在操作日志中可查

## 待澄清清单

1. **72 小时计算起点**：自动确认的 72 小时倒计时是否从「客服提交解决方案」时刻开始计算？精确到秒还是自然日？
2. **7 天申诉窗口计算方式**：7 天是按自然日（含/不含完成当天）还是按 168 小时精确计算？边界值「第 7 天当天」是否可申诉？
3. **申诉是否需要填写申诉理由**：PRD 未明确申诉时用户是否必须填写申诉内容，需确认是否为必填。
4. **管理员审批时效**：申诉提交后管理员审批是否有时间限制？超时是否自动通过或自动拒绝？
5. **转派是否可指定目标客服**：PRD 描述为「回到池中」，确认转派只能回到待分配池，不支持直接指定给特定客服。
6. **自动确认完成时间**：72 小时自动确认后，「已完成」时间记录为自动确认时刻还是解决方案提交时刻？该时间影响 7 天申诉窗口起算。
7. **并发判定机制**：用户撤单与客服接单并发时的「先到达」判定，是基于服务端接收时间还是数据库写入时间？是否存在毫秒级同时到达的特殊处理逻辑？
8. **申诉审批中工单状态**：用户提交申诉后、管理员审批前，工单状态是仍为「已完成」还是有中间态「申诉审批中」？
9. **转派次数限制**：同一工单是否限制转派次数？是否允许无限转派循环？
10. **非持有客服操作限制**：处理中工单，非当前持有客服是否可以查看工单内容？是否可以强制释放当前客服的持有关系？
