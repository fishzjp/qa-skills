> **测准声明**：本文件以 `user-service` 仓库 `main` 分支实际实现为唯一功能基线；需求摘要降为背景对照（偏离见附录）。代码级证据（`文件:行`、缺陷记录、接口对照）统一放文件末尾附录，**不写进用例正文**。

## 导读区

### 功能简介与角色表

| 角色 | 可做什么 |
|------|---------|
| 运营人员 | 通过后台注销违规用户 |
| 普通用户（会员） | 修改昵称、开通 VIP |
| 系统定时任务 | 每日凌晨 3 点执行搜索索引清理 |

### 环境与账号表

|------|------|
| 后台入口地址 | TODO：向运维索取运营后台访问地址 |

| 普通用户测试账号 | TODO：向开发索取测试用户 ID 列表（含有/无 VIP、有/无公开资料） |

### 术语表

| 术语 | 说明 |
|------|------|
| 硬删除 | 直接从数据库 DELETE 记录，行不再存在 |
| 软删除 | 标记 deleted=1，行保留（当前代码路径不使用） |
| 搜索索引 | 存储用户公开资料的可搜索索引，供用户搜索功能使用 |
| 宽限期 | VIP 到期时间在满月基础上多加 1 天 |
| user_profiles 表 | 用户公开资料表（头像、简介），随账号创建 |
| orders 表 | 历史订单表，通过 user_id 关联用户 |

### 图例

| 标记 | 含义 |
|------|------|
| [P0] | 冒烟测试，失败则核心功能不可用 |
| [P1] | 常规功能验证与常见异常处理 |
| [P2] | 边界、极端场景、需特殊环境 |
| （SMOKE-n） | 冒烟序号，便于快速抽取冒烟集 |
| 未标注优先级 | 默认 P1 |

### 执行模型说明

本模块均为后端服务功能（无 UI 代码），测试工程师无法独立执行。所有用例采用**协作五段式**：操作步骤标注「请开发执行」，预期结果标注「请开发反馈」，验证方式标明查库/查日志位置。

## 1. 用户注销

### 1.1 正常注销

> 前置：测试环境中存在可正常登录的用户，且该用户在 user_profiles 表有公开资料记录、在 orders 表有历史订单、在搜索索引中有记录、在缓存中有 profile 缓存。

- **TC-01-01 注销正常用户，账号被删除且缓存被清除** [P0]（SMOKE-1）
  - 前置条件: 用户 ID 1001 存在，缓存中有 key `user:profile:1001`
  - 操作步骤（请开发执行）: 1. 调用注销用户功能，传入用户 ID 1001 2. 查询 users 表确认该用户记录状态 3. 查询缓存 key `user:profile:1001` 是否存在
  - 预期结果（请开发反馈）: 返回结果含 deleted=true；users 表中 ID 1001 记录已不存在；缓存 key `user:profile:1001` 已删除
  - 验证方式: 开发查库 `SELECT * FROM users WHERE id=1001` 返回空；查缓存确认 key 已不存在

- **TC-01-05 注销后该用户不可再登录** [P0]（SMOKE-2）
  - 前置条件: 用户 ID 1004 此前可正常登录，记录其登录凭据
  - 操作步骤（请开发执行）: 1. 调用注销用户功能，传入用户 ID 1004 2. 使用该用户凭据尝试登录
  - 预期结果（请开发反馈）: 登录失败，返回用户不存在或已注销的提示
