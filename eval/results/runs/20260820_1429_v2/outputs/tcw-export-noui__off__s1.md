# 订单导出定时任务测试用例

## 1. 正常导出流程
### 1.1 日常正常导出
- **前置条件**：订单库存在前一日已完成订单数据，对象存储服务正常
- **操作**：模拟定时任务在凌晨2:00触发
- **预期**：
  - 查询前一日所有已完成订单，条数与DB实际一致
  - 生成CSV文件，列顺序为：订单号、用户ID、金额（分）、完成时间
  - CSV文件编码为UTF-8
  - 文件成功上传至 `oss://reports/orders/orders_YYYYMMDD.csv`
  - 导出记录表新增一条记录，含文件路径、条数、状态=成功

### 1.2 空数据导出
- **前置条件**：前一日无已完成订单
- **操作**：触发定时任务
- **预期**：
  - 生成仅含表头或空文件并上传（按设计约定）
  - 导出记录表新增一条记录，条数=0，状态=成功

## 2. 导出范围验证
### 2.1 时间范围准确性
- **场景**：前一日00:00:00–23:59:59（Asia/Shanghai）变为已完成的订单
- **边界用例**：
  - 完成时间 = 前一日 00:00:00 → 包含
  - 完成时间 = 前一日 23:59:59 → 包含
  - 完成时间 = 今日 00:00:00 → 不包含
  - 完成时间 = 前一日 00:00:00 前一秒 → 不包含
  - 完成时间 = 前一日 23:59:59 后一秒 → 不包含

### 2.2 订单状态过滤
- **场景**：仅导出状态为「已完成」的订单
- **用例**：
  - 前一日内「已完成」订单 → 导出
  - 前一日内「待支付/已取消/处理中」等非已完成订单 → 不导出
  - 前一日创建、今日才变为已完成的订单 → 不导出
  - 前一日完成、今日被退款/状态变更的订单 → 按设计确认是否导出（以完成时间落入前一日为准）

### 2.3 时区验证
- **场景**：服务器时区 Asia/Shanghai
- **用例**：
  - UTC时间前一日16:00:00（即北京时间前一日00:00:00）完成的订单 → 包含
  - UTC时间今日16:00:00（即北京时间今日00:00:00）完成的订单 → 不包含
  - 验证跨夏令时/非夏令时期间时间计算正确（Asia/Shanghai 无夏令时，确认不受影响）

## 3. CSV文件格式与内容
### 3.1 文件命名与路径
- 文件名格式：`orders_YYYYMMDD.csv`（如 `orders_20260819.csv`）
- 上传路径：`oss://reports/orders/orders_YYYYMMDD.csv`
- 日期部分对应前一日日期

### 3.2 CSV列定义
- 列顺序固定：订单号 | 用户ID | 金额（分） | 完成时间
- 表头行存在且列名正确
- 每行数据与列对应正确

### 3.3 数据格式验证
- 订单号：完整字符串，无截断
- 用户ID：完整字符串
- 金额：整数（分），非小数
- 完成时间：格式一致（验证具体格式如 `yyyy-MM-dd HH:mm:ss`）

### 3.4 特殊字符处理
- 订单号/用户ID含逗号 → CSV中正确转义（双引号包裹）
- 订单号/用户ID含双引号 → 转义为两个双引号
- 订单号/用户ID含换行符 → 正确处理
- 金额为0的订单 → 正常导出
- 金额为极大值（如 Long.MAX_VALUE）→ 正确导出

### 3.5 编码验证
- 文件编码为 UTF-8
- 含中文数据的订单 → 乱码验证
- BOM头处理（确认是否需要/不包含BOM）

## 4. 对象存储上传
### 4.1 上传成功
- 文件成功上传至目标路径
- 文件可下载且内容与本地生成一致
- 文件大小与内容匹配

### 4.2 上传失败-网络异常
- **场景**：上传时网络中断/超时
- **预期**：触发重试机制，最终成功或失败按重试逻辑处理

### 4.3 上传失败-权限不足
- **场景**：对象存储凭证失效或无写入权限
- **预期**：重试3次后失败，记录状态=失败，触发告警

### 4.4 上传失败-存储空间不足
- **场景**：对象存储空间不足
- **预期**：重试3次后失败，记录状态=失败，触发告警

## 5. 重试机制
### 5.1 首次失败后重试成功
- **操作**：模拟首次上传/查询失败
- **预期**：等待5分钟后重试，重试成功，最终状态=成功

### 5.2 多次失败后重试成功
- **操作**：模拟前2次失败、第3次成功
- **预期**：重试2次后成功，最终状态=成功，共重试2次

### 5.3 重试3次仍失败
- **操作**：模拟连续3次失败
- **预期**：
  - 不再继续重试
  - 导出记录表写入状态=失败
  - 触发告警通知

### 5.4 重试间隔验证
- 每次重试间隔为5分钟
- 重试期间不重复写入导出记录

### 5.5 不同失败步骤的重试
- 查询订单库失败 → 触发重试
- 生成CSV文件失败 → 触发重试
- 上传对象存储失败 → 触发重试
- 写导出记录失败 → 按设计确认是否重试或直接告警

## 6. 导出记录表
### 6.1 成功记录
- 字段完整性：文件路径、条数、状态=成功
- 文件路径与实际上传路径一致
- 条数与CSV行数一致（不含表头）

### 6.2 失败记录
- 字段完整性：文件路径（可能为空或部分路径）、条数（可能为0或查询到的条数）、状态=失败
- 失败原因记录（如有设计）

### 6.3 重复执行记录
- 同一天多次执行，每次新增一条导出记录
- 不更新已有记录

## 7. 幂等性与重跑
### 7.1 同一天重复执行-文件覆盖
- **操作**：同一天执行两次导出任务
- **预期**：
  - 第二次生成同名文件 `orders_YYYYMMDD.csv`
  - 对象存储中同名文件被覆盖
  - 文件内容以最新执行结果为准

### 7.2 同一天重复执行-记录新增
- **操作**：同一天执行两次导出任务
- **预期**：导出记录表新增两条记录（每次执行各一条）

### 7.3 重跑期间数据一致性
- **场景**：首次执行后，前一日数据发生变化（如补单/状态修正）
- **预期**：重跑覆盖生成新文件，内容反映最新数据

### 7.4 跨天补跑
- **场景**：手动触发补跑N天前的数据
- **预期**：按指定日期范围正确导出，文件名含对应日期

## 8. 性能与数据量
### 8.1 日常数据量（5万行）
- **预期**：任务在合理时间内完成（定义SLA，如10分钟内）
- 内存占用稳定，无OOM
- CSV文件正确生成并上传

### 8.2 大促数据量（500万行）
- **预期**：任务在可接受时间内完成（如30分钟内）
- 无内存溢出（流式写入/分批处理验证）
- CSV文件完整，行数与查询条数一致
- 上传大文件成功（断点续传/分片上传验证）

### 8.3 数据量边界
- 1行数据
- 0行数据（空文件）
- 超大单行数据（超长订单号/用户ID）

### 8.4 查询性能
- 500万行订单查询不超时
- 只读从库负载在可接受范围
- 查询SQL走索引（已完成状态+完成时间）

## 9. 依赖服务异常
### 9.1 订单库（只读从库）异常
- 从库连接失败 → 重试3次后失败，告警
- 从库数据延迟（主从同步延迟）→ 确认是否影响导出完整性
- 从库响应超时 → 重试或失败处理
- 从库不可用降级到主库 → 按设计确认

### 9.2 对象存储服务异常
- 服务完全不可用 → 重试3次后失败，告警
- 服务部分降级（可用率低于99.9%）→ 重试可能成功
- 上传速率极慢 → 超时处理

### 9.3 服务器时钟偏移
- 服务器时钟与标准时间偏差 → 确认日期计算是否受影响
- NTP同步异常 → 前一日范围计算可能出错

## 10. 并发与调度
### 10.1 任务重复触发
- 同一任务被重复调度（如调度框架重复触发）→ 幂等处理，不产生数据冲突
- 两个实例同时执行同一天导出 → 确认是否有分布式锁/并发控制

### 10.2 任务执行时间跨天
- 任务在凌晨2:00开始，执行时间超过当日 → 确认"前一日"范围不受影响（已在开始时确定）

### 10.3 前序任务未完成
- 上一日任务仍在重试中，新一日任务触发 → 确认是否排队/跳过/并行

## 11. 告警机制
### 11.1 告警触发条件
- 重试3次仍失败 → 触发告警
- 告警内容包含：失败任务日期、失败原因、重试次数

### 11.2 告警渠道
- 确认告警通知渠道（邮件/短信/IM）
- 告警接收人正确

### 11.3 告警不误触
- 任务正常成功 → 不触发告警
- 首次失败但重试成功 → 不触发告警
