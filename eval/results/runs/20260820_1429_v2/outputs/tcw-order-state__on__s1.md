## 导读区

### 功能简介与角色表

客服工单系统支持用户提交问题工单，由客服接单处理并提交解决方案，用户确认后关闭工单。核心是工单状态流转与并发控制。

| 角色 | 可执行操作 |
|------|-----------|
| 用户 | 创建工单、撤单（仅待分配状态）、确认解决、拒绝方案、申诉（已完成7天内） |
| 客服 | 接单、提交解决方案、转派 |
| 管理员 | 审批用户申诉 |

### 术语表

| 术语 | 含义 |
|------|------|
| 待分配 | 工单创建后的初始状态，尚未有客服接单，位于待处理池中 |
| 处理中 | 客服已接单，正在处理，与某客服建立持有关系 |
| 待用户确认 | 客服已提交解决方案，等待用户确认或拒绝 |
| 已完成 | 工单结束的正常终态（用户确认或72小时自动确认） |
| 已取消 | 工单结束的撤销终态（用户撤单） |
| 持有客服 | 当前处于"处理中"状态时，与工单绑定的唯一客服 |
| 转派 | 客服将工单退回待处理池，由其他客服接单 |
| 申诉 | 已完成工单在7天内由用户发起重新打开请求，需管理员审批 |

## 1. 待分配状态

### 1.1 进入待分配

> 前置：用户 user_test_01 已登录用户端；客服 agent_zhang 已登录客服工作台。

- **TC-01-01 用户创建工单后进入待分配状态** [P0]（SMOKE-1）
  - 操作步骤: 1. 进入用户端「我的工单」页面 2. 点击「提交工单」 3. 问题类型选择「账号问题」，标题填写「无法登录账号」，描述填写「输入正确密码后提示登录失败」 4. 点击「提交」
  - 预期结果: 页面提示提交成功，工单列表新增一条工单，状态显示为「待分配」，工单编号格式为 TK-开头

- **TC-01-02 转派后工单重新回到待分配** [P1]
  - 前置条件: 工单 TK-20240115-006 已被客服转派（详见 TC-02-03）
  - 操作步骤: 1. 客服 agent_zhang 登录客服工作台 2. 进入「待处理工单池」 3. 搜索 TK-20240115-006
  - 预期结果: 该工单出现在待处理池中，状态为「待分配」，工单详情可见转派记录与转派原因

### 1.2 客服接单（待分配 -> 处理中）

> 前置：客服 agent_zhang 已登录客服工作台。

- **TC-01-03 客服接单后工单变为处理中** [P0]（SMOKE-2）

  - 预期结果: 工单状态变为「处理中」，待处理池中该工单消失，该工单出现在 agent_zhang 的「我的工单」列表中

- **TC-01-04 接单后工单与客服建立持有关系** [P1]
  - 前置条件: 工单 TK-20240115-002 处于「待分配」状态
  - 操作步骤: 1. agent_zhang 在待处理池接单 TK-20240115-002 2. 打开该工单详情页

1. **72小时自动确认的起算时间**：是从客服提交解决方案的时刻开始计算，还是从用户收到通知的时刻开始计算？影响 TC-03-07/08/09 的时间 Mock 设置。

   - 影响模块：3.4 自动确认

3. **申诉是否存在独立的"审批中"状态**：用户提交申诉后、管理员审批前，工单状态是保持「已完成」并加标记，还是有独立的「申诉审批中」状态？PRD 状态机中未列出此中间状态。
   - 影响模块：4.1 用户申诉

4. **申诉审批通过后工单的客服归属**：是回到原持有客服，还是进入待分配池重新分配？PRD 未明确。
   - 影响模块：4.1 用户申诉

5. **7天申诉窗口的起算时间**：从工单「已完成」的时刻开始计算，还是从用户确认/自动确认的次日零点开始计算？边界值 TC-04-05/06 依赖此定义。
   - 影响模块：4.2 7天申诉窗口边界

6. **转派原因与拒绝理由的长度限制**：是否有最大字符数限制？是否允许特殊字符（emoji、引号、HTML 标签）？
   - 影响模块：2.3 转派原因校验、3.3 拒绝理由校验

7. **解决方案内容的长度限制与必填校验**：提交解决方案时内容是否必填？最大字符数？
   - 影响模块：2.1 提交解决方案

   - 影响模块：2.2 客服转派

9. **管理员审批入口的页面路径**：管理后台中「申诉审批」功能的导航路径。
   - 影响模块：4.1 用户申诉

10. **同一客服接单数量上限**：一个客服同时处于「处理中」状态的工单是否有数量上限？影响并发测试场景设计。
    - 影响模块：6.2 多客服并发接单
