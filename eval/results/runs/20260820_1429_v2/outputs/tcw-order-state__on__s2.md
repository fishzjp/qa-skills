# 客服工单系统 状态流转测试用例

## 导读

### 功能简介与角色表

本文件覆盖客服工单系统的核心状态流转功能。工单在「待分配 → 处理中 → 待用户确认 → 已完成/已取消」之间流转，涉及用户、客服、管理员三种角色的协作。

| 角色 | 可执行操作 |
|------|-----------|
| 用户 | 创建工单、撤单（仅待分配时）、确认解决、拒绝解决方案、申诉（已完成7天内） |
| 客服 | 接单、提交解决方案、转派（需填转派原因） |
| 管理员 | 审批用户申诉（通过/驳回） |

### 术语表

| 术语 | 中文名 | 解释 |
|------|--------|------|
| 待分配 | — | 工单创建后的初始状态，尚未有客服接单 |
| 处理中 | — | 客服已接单正在处理，同一工单同时仅允许一个客服持有 |
| 待用户确认 | — | 客服已提交解决方案，等待用户确认或拒绝 |
| 已完成 | — | 工单已结束（用户确认或72小时自动确认）；7天内可申诉重开 |
| 已取消 | — | 用户撤单导致的终态，不可再变更 |
| 转派 | — | 客服将处理中的工单退回待分配池，需填写转派原因 |
| 申诉 | — | 已完成的工单在7天内由用户发起重新打开请求，需管理员审批 |
| 持单客服 | — | 当前处于"处理中"状态时与工单有持有关系的客服 |

## 0. 状态机概览

**状态集**：待分配、处理中、待用户确认、已完成、已取消

**转换边**：
```
[创建] → 待分配
待分配 --客服接单--> 处理中
待分配 --用户撤单--> 已取消
处理中 --提交解决方案--> 待用户确认
处理中 --转派（需填原因）--> 待分配
待用户确认 --确认解决--> 已完成
待用户确认 --拒绝（需填理由）--> 处理中
待用户确认 --72h超时--> 已完成（系统自动确认）
已完成 --申诉（7天内，需管理员审批）--> 处理中
已取消 = 终态（不可变更）
已完成（超7天）= 终态（不可变更）
```

**终态**：已取消、已完成（超7天）

## 待澄清清单

1. **申诉流程中"需管理员审批"的具体含义**：用户提交申诉后，工单是否立即变为"处理中"，还是需管理员审批通过后才变为"处理中"？审批期间工单状态是什么？（影响 TC-04-01、TC-04-02 的预期结果）
2. **申诉重开后工单分配给谁**：管理员审批通过后，工单变为"处理中"，是分配给原处理客服还是回到待分配池？（影响 TC-04-02 的预期结果）
3. **72小时超时的起算时间点**：从工单进入"待用户确认"状态的时刻开始计算？精确到秒还是分钟？（影响 TC-03-07、TC-03-08 的边界值）
4. **"用户未操作"的定义**：仅指"确认解决"和"拒绝"操作，还是用户查看工单详情也算操作（会重置72小时计时）？（影响 TC-03-07 的测试设计）
5. **7天申诉窗口的起算时间点**：从工单变为"已完成"状态的时刻开始计算？第7天是否包含在内（即第7天23:59:59前仍可申诉）？（影响 TC-04-01、TC-04-04 的边界判定）
6. **管理员审批申诉是否有时限要求**：管理员未及时审批时如何处理？是否有超时自动通过/驳回机制？（影响申诉流程用例完整性）
7. **转派后原客服是否可以重新接同一工单**：转派后工单回到待分配池，原转派客服是否在接单列表中可见该工单？是否允许再次接单？（影响 TC-02-03 及可能的补充用例）
8. **拒绝后工单回到处理中时的持单关系**：拒绝后工单回到"处理中"，是否仍由原客服持有？原客服是否可以直接转派该工单？（影响 TC-03-02 的预期结果）
9. **转派原因和拒绝理由的字段限制**：是否有最大长度限制？支持的字符类型（emoji、特殊字符、HTML标签等）？（影响补充边界用例）
10. **72小时超时的检查机制**：系统是定时任务批量检查还是事件触发？检查频率是多少（每分钟/每5分钟/每小时）？（影响 TC-03-07 的判定时限"10分钟内"是否合理）
11. **客服工作台、用户端、管理后台的访问地址与测试账号**：当前环境信息缺失，需向测试组长索取。
12. **同一客服是否可同时持有多个"处理中"工单**：PRD仅约束"同一工单同时只能有一个客服持有"，未约束单个客服持有上限。（影响并发用例设计）
13. **工单是否有优先级字段**：是否影响待分配池中的接单顺序？（影响接单用例的测试数据准备）
