# 积分商城兑换 测试用例

### 功能简介与角色表

积分商城兑换功能：用户使用积分兑换商品，每次兑换扣减相应积分并减少库存。支持每人每日限兑3次（自然日），兑换接口幂等防重复扣分，兑换记录可在「我的-兑换记录」查看。

| 角色 | 用它做什么 |
|------|-----------|
| 普通用户 | 浏览积分商城、兑换商品、查看兑换记录 |
| 运营/管理员 | 上架商品、设置库存与积分价格（后台操作，非本文件测试范围） |

## 1. 兑换功能

### 1.1 正常兑换

> 前置：已登录测试用户A（积分余额≥2000）；积分商城已上架测试商品「蓝牙耳机」（积分价500，库存≥5）

- **TC-01-01 正常兑换商品，页面提示成功且积分余额减少** [P0]（SMOKE-1）
  - 操作步骤: 1. 进入积分商城页面（TODO：入口路径待向测试组长确认）2. 选择「蓝牙耳机」（积分价500）3. 点击「兑换」 4. 确认兑换
  - 预期结果: 页面提示「兑换成功」；积分余额减少500（如兑换前显示2000，兑换后显示1500，通过兑换前后页面上积分余额对比验证）

- **TC-01-02 库存仅剩1件时兑换成功** [P1]
  - 前置条件: 商品「限量马克杯」库存由运营后台调整为1
  - 操作步骤: 1. 进入积分商城页面 2. 选择库存为1的「限量马克杯」（积分价300）3. 点击「兑换」 4. 确认兑换
  - 预期结果: 页面提示「兑换成功」；积分余额减少300

- **TC-01-03 兑换成功后商品库存减少1** [P1]
  - 前置条件: 商品「蓝牙耳机」当前库存为N（N≥5），记录兑换前库存值
  - 操作步骤（请开发执行）: 1. 测试用户A兑换1件「蓝牙耳机」 2. 兑换完成后查询该商品库存
  - 预期结果（请开发反馈）: 兑换前库存为N，兑换后库存为N-1
  - 验证方式: 开发查询商品库存数据，反馈兑换前后库存值对比

### 1.2 兑换拦截

> 前置：已登录测试用户A（积分余额≥2000）和测试用户B（积分余额100）；积分商城已上架「蓝牙耳机」（积分价500，库存≥5）和库存为0的商品「限量马克杯」

- **TC-01-04 积分不足时兑换被拦截，积分不扣减** [P0]
  - 前置条件: 使用测试用户B登录（积分余额100，不足以兑换积分价500的「蓝牙耳机」）
  - 操作步骤: 1. 进入积分商城页面 2. 选择「蓝牙耳机」（积分价500）3. 点击「兑换」
  - 预期结果: 兑换未成功；页面显示积分不足的提示信息（如「积分不足，无法兑换」）；用户B积分余额仍为100，未扣减

- **TC-01-05 库存为0时兑换被拦截** [P1]
  - 前置条件: 商品「限量马克杯」库存已由运营后台设为0
  - 操作步骤: 1. 进入积分商城页面 2. 选择库存为0的「限量马克杯」 3. 点击「兑换」
  - 预期结果: 兑换未成功；页面显示库存不足或商品不可兑换的提示信息；用户积分余额不变

- **TC-01-06 每日兑换达3次后第4次被拦截** [P0]
  - 前置条件: 测试用户A当日尚未兑换；积分商城已上架「笔记本」（积分价100，库存≥4）
  - 操作步骤: 1. 连续兑换3次「笔记本」（积分价100，每次均成功） 2. 第4次选择任意商品点击「兑换」
  - 预期结果: 前3次均兑换成功，积分余额共减少300；第4次被拦截，页面显示今日兑换次数已达上限的提示信息（如「今日兑换次数已用完」）

- **TC-01-07 每日限额在自然日次日凌晨重置** [P2]
  - 前置条件: 测试用户A当日已兑换3次（达到每日限额），第4次被拦截
  - 操作步骤: 1. 等待至次日0:00后 2. 进入积分商城页面 3. 选择「笔记本」（积分价100）点击「兑换」
  - 预期结果: 次日0:00后兑换成功，不再提示次数上限
  - 备注: 若测试时间不允许跨天等待，可请开发协助重置用户当日兑换次数或修改服务器时间模拟跨天（具体方式TODO：与开发确认）

- **TC-01-08 积分不足被拦截后补充积分可正常兑换** [P1]
  - 前置条件: 测试用户B（积分余额100）兑换「蓝牙耳机」（积分价500）被拦截
  - 操作步骤: 1. 为用户B补充积分至≥500（补充方式TODO：向测试组长确认，如后台调整积分） 2. 再次选择「蓝牙耳机」点击「兑换」 3. 确认兑换
  - 预期结果: 补充积分后兑换成功，积分扣减500

### 1.3 幂等与防重复

> 前置：已登录测试用户A（积分余额≥2000）；积分商城已上架测试商品「蓝牙耳机」（积分价500，库存≥5）

- **TC-01-09 重复提交同一幂等请求只扣减一次积分** [P0]
  - 前置条件: 记录测试用户A当前积分余额X（如2000）
  - 操作步骤（请开发执行）: 1. 构造一条兑换「蓝牙耳机」的请求，携带幂等键K 2. 提交该请求，兑换成功 3. 使用相同幂等键K再次提交同一条兑换请求 4. 查询用户A积分余额与兑换订单
  - 预期结果（请开发反馈）: 第一次请求成功，积分扣减500（余额X-500）；第二次请求不重复扣分（余额仍为X-500），返回与第一次相同的结果或幂等提示
  - 验证方式: 开发查询用户积分扣减记录，确认只有一条扣减500的记录；查询兑换订单，确认只生成一笔订单

- **TC-01-10 快速连续点击兑换按钮只提交一次** [P1]
  - 操作步骤: 1. 进入积分商城页面 2. 选择「蓝牙耳机」 3. 在1秒内快速连续点击「兑换」按钮3次以上
  - 预期结果: 只兑换成功1次；积分余额只减少500（不减少1000或1500）；页面只出现1次成功提示

### 1.4 兑换记录

> 前置：测试用户A已成功兑换过至少1次（可在1.1用例执行后顺延执行）

- **TC-01-11 兑换成功后记录可在「我的-兑换记录」查看** [P1]
  - 操作步骤: 1. 完成一次成功兑换（如兑换「蓝牙耳机」） 2. 进入「我的」页面 3. 点击「兑换记录」
  - 预期结果: 兑换记录列表中显示刚才的兑换记录，包含兑换的商品名称

- **TC-01-12 兑换记录包含商品名称、扣减积分、兑换时间** [P1]
  - 前置条件: 测试用户A已兑换「蓝牙耳机」（积分价500），记录兑换发生的实际时间
  - 操作步骤: 1. 进入「我的」→「兑换记录」 2. 查看最近一条兑换记录的详细内容
  - 预期结果: 记录显示商品名称为「蓝牙耳机」；扣减积分为500；兑换时间与实际兑换发生时间一致（精确到分钟）

### 1.5 积分有效期

- **TC-01-13 次年3月31日积分统一清零** [P2]
  - 前置条件: 测试用户A有历史积分余额（如1500）
  - 操作步骤（请开发执行）: 1. 将服务器时间模拟至次年3月31日23:59 2. 确认用户A积分余额仍为1500 3. 将服务器时间推进至4月1日0:00 4. 查询用户A积分余额
  - 预期结果（请开发反馈）: 3月31日23:59积分余额仍为1500；4月1日0:00后积分余额变为0
  - 验证方式: 开发查询用户积分账户，确认余额在3月31日24:00后清零；若无法模拟服务器时间，改为开发确认积分清零定时任务的执行逻辑与触发条件（TODO：与开发确认清零任务实现方式）
