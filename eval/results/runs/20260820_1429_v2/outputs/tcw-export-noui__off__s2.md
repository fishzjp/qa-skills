# 订单导出定时任务测试用例

## 1. 正常导出场景
### 1.1 日常数据量导出
- 前置条件：前一自然日有少于5万条「已完成」订单，订单从库及OSS服务正常
- 操作步骤：模拟定时任务在凌晨2:00触发执行
- 预期结果：
  - 生成UTF-8编码的CSV文件并上传至`oss://reports/orders/orders_YYYYMMDD.csv`
  - 导出记录表新增一条记录，状态=成功，文件路径和条数正确
### 1.2 大促数据量导出
- 前置条件：前一自然日有约500万条「已完成」订单，订单从库及OSS服务正常
- 操作步骤：模拟定时任务触发执行
- 预期结果：
  - 成功生成CSV文件并上传至OSS，过程无内存溢出或超时
  - 导出记录表新增一条记录，状态=成功，条数与查询条数一致
### 1.3 空数据导出
- 前置条件：前一自然日无「已完成」订单
- 操作步骤：模拟定时任务触发执行
- 预期结果：
  - 生成仅含表头或空的CSV文件并上传至OSS
  - 导出记录表新增一条记录，状态=成功，条数=0

## 2. 数据正确性与边界验证
### 2.1 时间边界验证
- 前置条件：存在完成时间分别为前日00:00:00和23:59:59的订单
- 操作步骤：触发任务并检查导出文件
- 预期结果：两条边界订单均被包含在导出的CSV中
### 2.2 时区验证
- 前置条件：服务器部署在非Asia/Shanghai时区，或存在跨时区数据
- 操作步骤：触发任务
- 预期结果：严格按照Asia/Shanghai时区计算前一自然日00:00:00–23:59:59的范围进行数据筛选
### 2.3 状态过滤验证
- 前置条件：前一日存在多种状态（如待支付、处理中、已完成、已取消）的订单
- 操作步骤：触发任务并检查CSV内容
- 预期结果：CSV仅包含状态为「已完成」的订单，其他状态均被排除
### 2.4 CSV格式与列顺序验证
- 前置条件：正常触发导出
- 操作步骤：下载导出的CSV文件检查编码及列结构
- 预期结果：文件为UTF-8编码，列顺序依次为：订单号、用户ID、金额（分）、完成时间，金额单位正确为分

## 3. 幂等性与重跑机制
### 3.1 同日重复执行覆盖与记录
- 前置条件：当日已成功执行过一次导出任务
- 操作步骤：手动再次触发同一日期的导出任务
- 预期结果：
  - OSS中`orders_YYYYMMDD.csv`被新文件覆盖
  - 导出记录表不报唯一约束错误，新增一条导出记录

## 4. 异常处理与重试机制
### 4.1 OSS上传失败重试与恢复
- 前置条件：模拟首次上传OSS失败
- 操作步骤：触发任务，观察重试逻辑，并在第二次重试时恢复OSS服务
- 预期结果：任务在第5分钟后进行重试，第二次重试成功，导出记录表状态=成功
### 4.2 OSS上传最终失败
- 前置条件：模拟OSS服务持续不可用
- 操作步骤：触发任务，等待3次重试（间隔5分钟）完成
- 预期结果：重试3次后放弃，导出记录表新增记录状态=失败，触发告警通知
### 4.3 数据库查询超时/失败
- 前置条件：模拟订单只读从库连接异常或查询超时
- 操作步骤：触发任务
- 预期结果：触发重试机制，3次重试后仍失败，记录状态=失败并触发告警
### 4.4 重试间隔验证
- 前置条件：模拟导出过程异常
- 操作步骤：记录每次重试的时间戳
- 预期结果：重试严格按间隔5分钟执行，最大重试次数为3次

## 5. 依赖环境异常
### 5.1 订单只读从库延迟
- 前置条件：只读从库存在高延迟（如延迟超过1小时）
- 操作步骤：凌晨2:00触发任务
- 预期结果：任务按当前从库可见数据导出（待确认是否需检测延迟并阻断），不产生进程崩溃
### 5.2 对象存储可用率降级
- 前置条件：OSS处于高负载或局部故障（可用率低于99.9%）
- 操作步骤：触发任务
- 预期结果：触发重试机制，验证最终是否能在重试内成功或正确记录失败并告警

## 6. 待澄清清单
- 告警通知的接收方式与接收人配置（如邮件、企微/钉钉等）？
- 导出记录表在状态=失败时，文件路径和条数字段如何赋值（NULL或0或保留上一次成功值）？
- 导出500万行大促数据时，是否有执行超时阈值（如2小时内必须完成）？
- 500万行CSV大小较大，是否需要开启GZIP压缩？若压缩，文件名是否变为`.csv.gz`？
- 空数据导出时，CSV文件是否需要包含表头行？
- 数据库从库存在高延迟时，是否需要增加延迟阈值判断并中断任务？
- 同日多次重跑产生多条成功记录，是否需要保留历史记录或在记录表增加版本号/执行批次号以便追溯？
