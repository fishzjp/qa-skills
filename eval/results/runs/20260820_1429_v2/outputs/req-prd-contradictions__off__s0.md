# 会员积分体系 需求模型

> 版本：v0.9（草稿） | 基于输入 PRD v0.9 分析

---

## 一、需求目标

| 编号 | 目标 | 说明 |
|------|------|------|
| O-01 | 提升用户活跃 | 通过签到、评价等行为激励用户日常参与 |
| O-02 | 提升复购 | 通过消费返积分与积分抵现形成消费闭环 |
| O-03 | 建立积分获取与消耗闭环 | 获取（消费/签到/评价）↔ 消耗（兑换/抵现）形成正向循环 |

---

## 二、功能范围

### 2.1 功能范围（含）

| 模块 | 功能点 |
|------|--------|
| 会员等级 | 等级划分（普通/银卡/金卡/铂金?）、积分获取系数差异化 |
| 积分获取 | 消费返积分、每日签到、连续签到奖励、评价订单返积分 |
| 积分消耗 | 积分商城兑换、下单积分抵现 |
| 积分生命周期 | 状态管理（正常/冻结/已消耗/已过期）、有效期管理 |
| 退款处理 | 订单退款时积分扣回 |
| 风控对接 | 异常行为扣分（依赖风控系统） |

### 2.2 非目标

| 编号 | 非目标 | 说明 |
|------|--------|------|
| NO-01 | 会员等级升级/降级规则 | PRD 未定义等级变动条件与机制 |
| NO-02 | 积分转赠/转移 | 未提及用户间积分流转 |
| NO-03 | 积分兑换现金/提现 | 仅支持商城兑换与下单抵现 |
| NO-04 | 积分商城商品管理 | 商品上架/定价/库存不属于本体系范围 |
| NO-05 | 积分活动运营配置 | 未提及限时多倍积分等运营活动机制 |

## 五、状态与流转

### 5.1 积分状态定义

| 状态 | 说明 |
|------|------|
| 正常 | 可用积分，可用于兑换与抵现 |
| 冻结 | 用户发起兑换后临时锁定，不可重复使用 |
| 已消耗 | 兑换成功，积分已消耗 |
| 已过期 | 年度清零或过期失效，不可恢复 |

### 5.2 积分状态流转图

```
                       ┌─────────────┐
                 发起兑换│   冻结      │
            ┌──────────>│ (Frozen)    │
            │           └──────┬──────┘
            │           兑换成功│      兑换失败
            │                  ▼        │
┌───────────┐            ┌──────────┐   │
│   正常    │            │ 已消耗   │   │
│ (Normal)  │            │(Consumed)│   │
└─────┬─────┘            └──────────┘   │
      │       <─────────────────────────┘
      │        解冻回正常
      │
      │ 年度清零/过期
      ▼
┌───────────┐
│  已过期   │
│ (Expired) │
└───────────┘
```

### 5.3 流转规则

| 编号 | 流转规则 | 来源 |
|------|----------|------|
| ST-01 | 积分获取后初始状态为"正常" | 推断（PRD 未明确） |
| ST-02 | 正常 → 冻结：用户发起兑换 | PRD-积分状态 |
| ST-03 | 冻结 → 已消耗：兑换成功 | PRD-积分状态 |
| ST-04 | 冻结 → 正常：兑换失败解冻 | PRD-积分状态 |
| ST-05 | 正常 → 已过期：年度清零触发 | PRD-附注（与"永久有效"矛盾，待澄清） |

### 5.4 待确认流转

| 编号 | 场景 | 问题 |
|------|------|------|
| STQ-01 | 退款扣回时积分处于"冻结"状态 | 是否优先扣冻结积分？还是仅扣正常积分？ |
| STQ-02 | 年度清零时积分处于"冻结"状态 | 冻结积分是否一并清零？ |
| STQ-03 | 风控扣分时积分不足 | 积分状态如何变更？是否允许负数？ |
| STQ-04 | 抵现下单时积分状态 | 抵现是否也走"冻结→已消耗"流程？PRD 仅描述兑换走冻结流程 |
