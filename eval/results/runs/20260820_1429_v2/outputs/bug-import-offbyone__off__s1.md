# BUG-2077：批量导入优惠券失败行的行号提示错位一行 根因分析

## 1. 根因定位
- **根因位置**：`coupon-import` 模块 `importer.py` 第 31 行
- **根因说明**：
  在 `import_coupons` 函数中，当捕获到 `ValidationError` 时，使用 `reader.line_num + 1` 计算错误行号。
  Python 的 `csv.DictReader` 在读取数据时，`line_num` 属性记录的是当前从源迭代器读取的物理行号（该行号**已经包含表头行**）。当读取到 CSV 第 3 行的数据时，`reader.line_num` 的值即为 3。
  此处额外执行 `+ 1` 操作，导致计算出的行号变为 4，使得错误提示行号比实际物理行号大 1。

## 2. 影响范围分析
- **功能影响**：管理后台“券工场”的“批量导入优惠券”功能。当导入的 CSV 文件中存在违反业务校验规则（如面额超限、使用门槛低于面额等抛出 `ValidationError` 的场景）的行时，返回给用户的错误提示行号均会比实际 CSV 物理行号大 1，误导用户排查问题。
- **逻辑不一致影响**：根据代码逻辑，抛出 `ValidationError` 的行号计算加了 1（L31），而抛出其他 `Exception` 的行号计算未加 1（L34，`line_no = reader.line_num`）。这会导致在同一批导入失败的数据中，业务校验错误与系统错误的行号提示逻辑不一致。

## 3. 修复建议
修改 `coupon-import` 模块 `importer.py` 第 31 行的行号计算逻辑，去除多余的 `+ 1`，使其与 `reader.line_num` 的实际含义及其他异常分支的处理保持一致。

**修改前：**
```python
line_no = reader.line_num + 1       # L31: line_num 已含表头行，再 +1 多算一行
```

**修改后：**
```python
line_no = reader.line_num           # L31: line_num 已包含表头行，直接使用即为 CSV 实际物理行号
```

## 4. 回归建议
针对“券工场 - 批量导入优惠券”功能进行回归测试，重点覆盖以下场景：
1. **单行校验失败场景**：准备 CSV 文件（第1行表头，第2行合法数据，第3行面额超限），验证提示错误行号为“第 3 行”。
2. **首行数据失败场景**：准备 CSV 文件（第1行表头，第2行面额超限），验证提示错误行号为“第 2 行”。
3. **尾行数据失败场景**：准备 CSV 文件（第1行表头，第2行合法，第3行合法，第4行门槛低于面额），验证提示错误行号为“第 4 行”。
4. **混合错误类型场景**：准备 CSV 文件，包含触发 `ValidationError`（如面额超限）和触发系统 `Exception`（如缺少必填列导致 KeyError/ValueError）的行，验证两种错误类型的提示行号均与 CSV 实际物理行号一致。
5. **全部合法场景**：准备全部合法的 CSV 文件，验证成功导入且无错误提示。
