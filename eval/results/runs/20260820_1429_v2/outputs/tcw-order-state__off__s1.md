# 客服工单系统状态流转测试用例

## 一、正向状态流转测试

### 1.1 工单创建 → 待分配
- 用例ID：TC-ST-001
- 角色：用户
- 前置条件：用户已登录客服工作台 Web 页面
- 操作步骤
  - 用户进入工单创建页面
  - 填写工单标题、描述等信息
  - 点击「提交」按钮
- 预期结果
  - 页面提示工单创建成功
  - 工单状态显示为「待分配」
  - 工单出现在待分配工单池中
  - 工单创建时间被正确记录

### 1.2 待分配 → 处理中（客服接单）
- 用例ID：TC-ST-002
- 角色：客服
- 前置条件：工单处于「待分配」状态，客服已登录工作台
- 操作步骤
  - 客服在工单池中看到该待分配工单
  - 点击「接单」按钮
- 预期结果
  - 工单状态变更为「处理中」
  - 工单从待分配池中移除
  - 工单与该客服建立持有关系，页面显示当前处理客服为该客服
  - 接单时间被正确记录

### 1.3 待分配 → 已取消（用户撤单）
- 用例ID：TC-ST-003
- 角色：用户
- 前置条件：工单处于「待分配」状态，用户已登录
- 操作步骤
  - 用户进入「我的工单」列表
  - 找到该待分配工单，点击「撤单」按钮
  - 确认撤单操作
- 预期结果
  - 工单状态变更为「已取消」
  - 工单从待分配池中移除
  - 撤单时间被正确记录
  - 工单变为终态，不可再变更

### 1.4 处理中 → 待用户确认（客服提交解决方案）
- 用例ID：TC-ST-004
- 角色：客服
- 前置条件：工单处于「处理中」状态，由该客服持有
- 操作步骤
  - 客服在工单详情页填写解决方案内容
  - 点击「提交解决方案」按钮
- 预期结果
  - 工单状态变更为「待用户确认」
  - 解决方案内容保存成功并展示在工单详情中
  - 用户侧收到待确认通知
  - 提交时间被正确记录

### 1.5 处理中 → 待分配（客服转派）
- 用例ID：TC-ST-005
- 角色：客服
- 前置条件：工单处于「处理中」状态，由该客服持有
- 操作步骤
  - 客服在工单详情页点击「转派」按钮
  - 在弹窗中填写转派原因（如"需要二线技术支持"）
  - 点击「确认转派」
- 预期结果
  - 工单状态变更为「待分配」
  - 工单回到待分配工单池
  - 转派原因被正确记录并可在工单详情中查看
  - 原客服的持有关系解除
  - 转派操作时间被正确记录

### 1.6 待用户确认 → 已完成（用户确认解决）
- 用例ID：TC-ST-006
- 角色：用户
- 前置条件：工单处于「待用户确认」状态，用户已登录
- 操作步骤
  - 用户进入工单详情页，查看解决方案
  - 点击「确认已解决」按钮
- 预期结果
  - 工单状态变更为「已完成」
  - 确认时间被正确记录
  - 工单进入已完成列表，7 天内可申诉

### 1.7 待用户确认 → 处理中（用户拒绝，附拒绝理由）
- 用例ID：TC-ST-007
- 角色：用户
- 前置条件：工单处于「待用户确认」状态，用户已登录
- 操作步骤
  - 用户进入工单详情页，查看解决方案
  - 点击「未解决/拒绝」按钮
  - 在弹窗中填写拒绝理由（如"问题仍然存在"）
  - 点击「确认提交」
- 预期结果
  - 工单状态变更为「处理中」
  - 拒绝理由被正确记录并展示在工单详情中
  - 工单回到原持有客服的处理队列
  - 拒绝操作时间被正确记录

### 1.8 待用户确认 → 已完成（72 小时超时自动确认）
- 用例ID：TC-ST-008
- 角色：系统（自动）
- 前置条件：工单处于「待用户确认」状态
- 操作步骤
  - 模拟或等待工单进入「待用户确认」状态满 72 小时，用户无任何操作
- 预期结果
  - 系统自动将工单状态变更为「已完成」
  - 工单详情中标注「系统自动确认」标识
  - 自动确认时间为 72 小时到期时刻
  - 工单进入已完成列表，7 天内可申诉

### 1.9 已完成 → 处理中（用户申诉，7 天内，管理员审批通过）
- 用例ID：TC-ST-009
- 角色：用户、管理员
- 前置条件：工单处于「已完成」状态，且距完成未超过 7 天
- 操作步骤
  - 用户进入已完成工单详情页
  - 点击「申诉」按钮，填写申诉理由
  - 管理员登录工作台，进入申诉审批列表
  - 管理员查看申诉内容，点击「审批通过」
- 预期结果
  - 用户申诉提交后，工单生成申诉记录，等待审批
  - 管理员审批通过后，工单状态变更为「处理中」
  - 工单重新打开，回到处理队列
  - 申诉理由与审批结果均被记录

## 二、终态验证测试

### 2.1 已取消为终态，不可变更
- 用例ID：TC-ST-010
- 角色：用户、客服
- 前置条件：工单处于「已取消」状态
- 操作步骤
  - 用户尝试对已取消工单执行确认、拒绝、申诉等操作
  - 客服尝试对已取消工单执行接单、提交方案、转派等操作
- 预期结果
  - 所有操作按钮不可点击或不展示
  - 若通过接口直接调用，返回错误提示"工单已取消，不可操作"
  - 工单状态保持「已取消」不变

### 2.2 已完成超 7 天为终态，不可变更
- 用例ID：TC-ST-011
- 角色：用户
- 前置条件：工单处于「已完成」状态，且距完成时间超过 7 天
- 操作步骤
  - 用户进入已完成工单详情页
  - 查看是否有申诉按钮
- 预期结果
  - 「申诉」按钮不可见或置灰不可点击
  - 若通过接口直接调用申诉，返回错误提示"已超过申诉时效"
  - 工单状态保持「已完成」不变

### 2.3 已完成未超 7 天不可直接变更状态（需申诉审批）
- 用例ID：TC-ST-012
- 角色：用户
- 前置条件：工单处于「已完成」状态，未超过 7 天
- 操作步骤
  - 用户点击「申诉」按钮并提交申诉理由
  - 在管理员审批前，查看工单状态
- 预期结果
  - 申诉提交后工单状态仍为「已完成」，不直接变为「处理中」
  - 需等待管理员审批通过后才变更为「处理中」

## 四、并发与互斥测试

### 4.1 用户撤单与客服接单并发（撤单先到）
- 用例ID：TC-ST-017
- 角色：用户、客服
- 前置条件：工单处于「待分配」状态
- 操作步骤
  - 模拟用户撤单请求与客服接单请求几乎同时发出
  - 撤单请求先到达服务器
- 预期结果
  - 工单状态变更为「已取消」
  - 客服接单请求失败，页面提示"工单已被取消"或类似信息
  - 工单不与客服建立持有关系

### 4.2 用户撤单与客服接单并发（接单先到）
- 用例ID：TC-ST-018
- 角色：用户、客服
- 前置条件：工单处于「待分配」状态
- 操作步骤
  - 模拟用户撤单请求与客服接单请求几乎同时发出
  - 接单请求先到达服务器
- 预期结果
  - 工单状态变更为「处理中」
  - 用户撤单请求失败，页面提示"工单已被客服接单，无法撤单"或类似信息
  - 工单与客服建立持有关系

### 4.3 同一工单同时只能有一个客服持有
- 用例ID：TC-ST-019
- 角色：客服A、客服B
- 前置条件：工单处于「待分配」状态
- 操作步骤
  - 客服A 与客服B 同时对同一工单点击「接单」
- 预期结果
  - 仅一名客服接单成功，工单状态变为「处理中」
  - 另一名客服接单失败，提示"工单已被其他客服接单"
  - 工单持有关系仅与接单成功的客服绑定

### 4.4 处理中状态其他客服尝试接单
- 用例ID：TC-ST-020
- 角色：客服A（持有）、客服B
- 前置条件：工单处于「处理中」状态，由客服A 持有
- 操作步骤
  - 客服B 尝试对该工单执行接单操作
- 预期结果
  - 接单操作不可用或失败
  - 提示"工单正在处理中"或类似信息
  - 工单持有关系不变，仍为客服A

## 九、转派循环与记录测试

### 9.1 转派后其他客服接单
- 用例ID：TC-ST-037
- 角色：客服A、客服B
- 前置条件：工单由客服A 持有，处于「处理中」状态
- 操作步骤
  - 客服A 填写转派原因并转派，工单回到「待分配」
  - 客服B 在工单池中接单
- 预期结果
  - 客服B 接单成功，工单状态变为「处理中」
  - 工单持有关系变更为客服B
  - 转派原因及历史记录可在工单详情中查看

### 9.2 多次转派后转派记录完整
- 用例ID：TC-ST-038
- 角色：客服A、客服B、客服C
- 前置条件：工单处于「待分配」状态
- 操作步骤
  - 客服A 接单 → 转派（原因1）→ 客服B 接单 → 转派（原因2）→ 客服C 接单
- 预期结果
  - 每次转派原因均被完整记录
  - 转派历史可追溯，包含每次转派的客服、时间、原因
  - 最终工单由客服C 持有，状态为「处理中」

### 9.3 同一客服接回自己转派的工单
- 用例ID：TC-ST-039
- 角色：客服A
- 前置条件：工单由客服A 转派后处于「待分配」状态
- 操作步骤
  - 客服A 再次从工单池中接回该工单
- 预期结果
  - 接单成功，工单状态变为「处理中」
  - 工单持有关系重新绑定客服A
  - 转派历史记录保留
