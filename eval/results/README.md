### 方法论修复记录（本轮落地，对应审查报告的全部问题）

1. **多样本生成**（n=3）+ 任务层配对 bootstrap 95%CI —— 校准轮 +28.8pp 的"状态机强提升"被证明不可复现，单采样结论的教训实证
2. **成对评审 + 位置互换**（MT-Bench 式）—— 23 对：1 胜/1 负/21 平（另 1 对调用失败未计入，n=23/24）；同源 judge 倾向打平，异构 judge 复测为遗留项
3. **标注独立审计**（12/12，一致率均值 **0.872**；两个任务一致率 0.55/0.57，flagged 项已人工逐条复核；e2e-markmap-to-spec 的审计有 4/8 条未解析、其 annotation 的 audit 字段待补录）+ 人工逐条复核：22 处接受（含 1 处作者事实错误 `>=` 语义写反、3 处超范围移出）、1 处有理拒绝、9 个材料可推导补充 → 119 可测点 + 48 检出项
4. **真实执行环境**：E2E mock 应用（语义化菜单、异步数据加载，与任务材料一致）+ chromium 双跑稳定检测；API mock 服务（OpenAPI 契约全实现）+ pytest——执行指标完全脱离 judge
5. **门冻结与预注册**（EXPECTED.md v1.0）——本轮 3 门失败如实记录；G4 的截断失败已修复进 skill（输出预算纪律）；v1.1 门提案以本轮估计导出，只约束下一轮

### 诚实声明

- 本轮 judge 与生成同源（glm-5-2），覆盖/质量/成对的绝对值可能存在同源宽容偏差（Off 覆盖或被高估、成对多平局）；**客观指标（可执行性/编译/真实执行/检出用例中的植入 bug）不受此影响**
