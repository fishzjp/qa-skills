# 预期效果门（Benchmark 合入判定标准）

> Skill 改动跑黄金集，指标回退或未达预期则拦截合入（Skill 也需要 CI）。以下门槛在 `run_eval.py score` 阶段自动判定，全部 ✅ 才算"达到预期效果"。

| 门 | 判定 | 依据 |
|----|------|------|
| G1a 覆盖提升（均值） | tcw 类任务（5 个）有效覆盖均值 On ≥ Off + 5pp | v2 §12.2 Coverage；防回退 + 温和提升 |
| G1b 覆盖提升（方法敏感） | 状态机任务（tcw-order-state）On ≥ Off + 20pp | Skill 的状态机/覆盖方法直接作用处应有强提升 |
| G2 可执行性 | tcw 类 On 可执行性均分 ≥ 0.75 | v2 §7.6/§12.2 Executability 一票否决——Skill 的核心增量就是可执行性 |
| G3 Bug 检出 | 代码任务（tcw-user-delete-code）On 检出 ≥ 75%（4 个植入 bug ≥ 3 个） | v2 §12.2 Bug Finding |
| G4 编译通过 | 代码类任务（api / e2e）On 编译通过率 100% | v2 §12.2 自动化指标 Compilation Success Rate |
| G5 质量 | 质量均分 On ≥ 0.8（4.0/5.0）且 ≥ Off | v2 §12.2 Quality（LLM-as-judge） |
| G6 整体不劣 | On 在 ≥ 2/3 有可比指标的任务上不劣于 Off（-10pp 容差） | 防止局部改善整体回退 |

> **G1 修订记录（2026-08-20，v0 首轮实测后）**：原 G1 为"tcw 均值 +15pp"。实测发现无 Skill 基线（glm-5-2）在通用 PRD 枚举类任务上覆盖已达 ~84%（饱和），统一 +15pp 的门槛隐含了弱基线假设，不成立；Skill 的覆盖增益集中在方法敏感任务（状态机 +30pp、增量 +12.5pp），通用任务打平。据此拆为 G1a（均值 +5pp 底线）与 G1b（方法敏感 +20pp），防回退语义不变（G6 仍兜底全任务）。可执行性、检出率、质量、编译四项门未调整。同轮修订：coupon-prd 标注中 3 个属于「领取/结算」功能的点移出分母（标注过宽，任务目标为「创建」功能）；judge prompt 补"表格行 Cx 记录同样算检出"。

## 已知限制（黄金集 v0 如实声明）

- v0 黄金集由 Agent 标注（可测点清单 / 植入 bug / 判定基准），**尚未经人工交叉复核**；v2 §12.3① 的人工分母要求在扩容前完成（每任务约 4–8 小时专家时间）
- 单样本（多样本采样与置信区间为 Benchmark 扩容项）；judge 为 LLM-as-judge + 固定 rubric，未做 20% 人工抽检校准
- Executability 客观检查为正则启发式（占位符/模糊判定/正文代码/异步时限/导读四件套），模拟执行评估（逐步走一遍）为人工环节，不入自动分
- On 模式加载的 skill 文件清单记录在各任务 `annotation.json` 的 `skill_files_on`（对应渐进披露），两模式任务输入完全相同
