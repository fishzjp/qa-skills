# Bug 分析（bug-analysis）

对**已确认**的 Bug 做根因定位、影响分析、回归建议。

- **输入**：Bug 报告（现象 + 复现步骤 + 证据）、代码仓库、（可选）需求模型 / 测试用例
- **输出（落盘）**：Bug 条目（结构见下），**追加进测试报告**（`../core/report-template.md` §3 的"根因分析 / 回归建议"两段即本 skill 的填写范围）
- **边界**：输入是**已确认**的 Bug（用户或执行结果已定性"这是缺陷"）；审查发现的**疑似**缺陷（待验证）归 `test-case-writing` 的 Cx 记录；回归**范围选择**归 `regression-testing`

## When NOT to Use

- 还没定性（"这是 Bug 还是特性？"）→ 先经用户裁决（Bug 定性检查点，见 `qa`）；证据收集阶段 → `automated-e2e-testing` 工作流二 / `api-testing`
- 代码审查发现的疑似缺陷（未复现、未定性）→ `test-case-writing` 的 Cx 缺陷记录（待实测确认）
- 需要回归清单（哪些用例要跑）→ `regression-testing`（本 skill 产出回归用例**建议**）
- 端到端流水线 → `qa` 编排（本 skill 是其阶段 6）

## Bug 条目结构（追加进测试报告）

字段与 `../core/report-template.md` §3 完全一致（前 8 个字段为模板原有；影响范围 / Severity 依据 / 修复建议 为本 skill 的扩展字段，模板中标注为可选）：

```markdown
### BUG-{序号}: {简要描述}

- **严重程度**: P0 / P1 / P2
- **发现方式**: 自动化测试 / 探索性测试 / 业务熟悉探索 / 手动执行 / 代码审查（Cx 转）
- **复现步骤**: 1. … 2. … 3. …（确定性复现；概率性注明频率与环境）
- **预期行为**: {依据：需求文档章节 / 测试用例 TC 编号}
- **实际行为**: {一句话现象}
- **证据**: {证据链：复现日志/截图 + 根因代码 `文件:行`，等级标注见 `../core/evidence.md`}
- **环境**: {URL} / {账号角色}
- **根因分析**: {Root Cause 结论 + status 标注：Inference（读代码推断）/ Verified（已复现验证 E3）}
- **影响范围**: {受影响功能/数据/用户面，逐条给来源}
- **Severity 依据**: {资损/数据丢失/功能不可用/体验 → 对应 P 级}
- **修复建议**: {给开发的修复方向，不越界写补丁}
- **回归建议**: {修复后应验证的用例编号或场景 + 是否需要新增回归用例}
```

## 工作流

### 1. 复现（先拿到稳定证据）

- 按 Bug 报告步骤复现；复现不了 → 不硬分析，区分"环境差异 / 数据依赖 / 概率性"，向用户要环境与数据线索
- 复现过程采集证据：请求/响应原文、日志、截图（E3 运行证据）

### 2. 读代码定位根因

- 从现象入口（页面/接口）向下追：入口 → 调用链 → 数据读写，定位到**具体行为与预期的分叉点**（`文件:行`）
- 检查常见根因类别：边界未防护 / null 未兜底 / 状态竞态 / 事务不完整 / 缓存不一致 / 权限漏判 / 并发覆盖 / 配置漂移
- 根因结论标注 status：**Inference**（代码推断，未运行验证）或 **Verified**（已通过复现/最小实验验证，E3）——不伪装推断为事实

### 3. 影响分析

- **功能面**：同一根因会波及哪些入口/路径（grep 相同模式的其他调用点）
- **数据面**：是否已产生脏数据、影响存量数据的范围
- **用户面**：受影响角色与操作路径

### 4. 定级与修复建议

- Severity 按后果分级：数据丢失/资损/安全 → P0；核心功能**主路径**不可用 → P0，核心功能**旁路**不可用 → P1；部分降级 → P1；体验问题 → P2
- 修复建议给**方向**（如"导入路径补同创建路径的校验"），不越界替开发写补丁

### 5. 回归建议（衔接 regression-testing）

- 修复验证用例：直接复现该 Bug 的用例（没有则建议新增，给 TC 编号建议）
- 关联回归：同根因模式的其他路径 + 该功能的锚点用例
- 回归**范围选择**（跑哪些既有用例、分级）移交 `regression-testing`

### 6. 落盘

Bug 条目追加进测试报告对应条目（补"根因分析 / 回归建议"两段）；无报告时新建报告文件（按 `../core/report-template.md`）。

## Common Mistakes

| 错误 | 后果 | 正确做法 |
|------|------|---------|
| 未复现就开始分析 | 根因建立在想象上 | 先复现拿 E3 证据；复现不了先要线索 |
| 根因推测定性为事实 | 虚假结论传播 | status 标注 Inference/Verified（`../core/evidence.md`） |
| 现象当根因（"接口超时，根因：接口超时"） | 分析空转 | 追到行为与预期分叉的 `文件:行` |
| 影响范围只看单点 | 同根因其他路径漏修漏测 | grep 相同模式，功能/数据/用户三面分析 |
| 越界写补丁代码 | 职责越界、干扰开发 | 给修复方向与验证建议 |
| 把回归范围选择也做了 | 与 regression-testing 职责重叠 | 本 skill 出回归**建议**，范围选择移交 |
| 疑似缺陷（未定性）直接进本流程 | 与 Cx 记录职责混淆 | 输入必须是已确认 Bug；未定性先走裁决 |
