01 · Why

软件发布之前，Before release,
先把质量问题找出来find the risks that matter

软件上线前，需要验证各种业务场景： 并发下单会不会超卖？优惠券到期会不会自动失效？接口异常时数据会不会错乱？

Before launch, a team needs to check how its software behaves: Can concurrent orders oversell stock? Do coupons expire on time? Can an API failure leave data inconsistent?

软件测试工程师的工作，就是 尽早发现缺陷、分析原因，并验证修复结果。

A QA engineer helps answer these questions: find defects early, investigate their causes and verify the fixes.

qa-skills 把这些测试方法整理成 AI 助手可读取的指令。qa-skills turns these testing methods into instructions your AI agent can follow.

上线前要回答的问题Questions to answer before launch

优惠券到期Coupon expiry ··· 到期后还能不能使用？Can an expired coupon still be used?
接口重试API retries ··· 会不会重复扣款？Double charges?
权限变更Permission changes ··· 旧会话还能不能用？Do old sessions still work?

02 · Problem

测试用例，要让人看得懂、执行得了。Test cases need to be clear enough to run.

AI 生成的用例可能看似完整，却缺少执行所需的信息：
预期结果模糊、占位符未替换、没有等待时限，或指向不存在的入口。
qa-skills 用明确的编写和评审标准，帮助发现这些问题。

AI-generated cases can look complete while missing essential details:
vague expected results, unresolved placeholders, no time limits or nonexistent entry points.
qa-skills provides writing and review criteria to catch these gaps.

✗ 常见的问题写法✗ An unclear test case CASE-001

缺少明确的通过标准No clear pass criteria

只写“正常”，执行者无法判断是否通过：“Works correctly” does not tell the tester what to check:

「检查优惠券功能是否正常」
「正常」是什么标准？谁判定？等多久算超时？
“Check that the coupon feature works correctly”
What does “correctly” mean? What should happen, and how long should the tester wait?

没有明确的判定标准，就无法确认测试是否通过。Without clear pass criteria, a tester cannot verify the result.

✓ 产出示例节选✓ Excerpt from a generated case TC-03-05

写清步骤和判定时限Specific steps and time limits

说明前置条件、操作步骤、预期结果和等待时限：State the preconditions, steps, expected result and time limit:

「选一张 10 分钟后到期 的已发布优惠券，等待到期。
预期：1 小时内状态自动变为「已结束」，
超过 1 小时即判失败。」
“Pick a published coupon expiring in 10 minutes, and wait.
Expected: status changes to “Ended” automatically within 1 hour;
any longer counts as a failure.”

查看完整用例。执行前，还需确认测试环境、账号和操作入口。Read the full case. Before running the case, confirm the environment, account and entry points.

让拿到用例的人知道：
从哪里开始、如何操作、怎样判断结果。 共享知识库提供 8 条可执行性标准，用于编写、自检和评审。 A tester should know:
where to start, what to do and how to judge the result. Eight executability standards guide writing, self-checks and review.

List the expected test points, then check case coverage, steps and pass criteria against that baseline. Revise the files and record the review results.

Reproduce the issue, then investigate logs and code to assess its cause and impact. Separate confirmed facts from hypotheses and recommend regression checks.

07 · FAQ

安装和使用前，Before you get started,
先了解这些问题。a few things to know.

费用、兼容性、执行条件和语言支持，都在这里说明。

Costs, compatibility, execution requirements and language support.

qa-skills 是什么？要花钱吗？What is qa-skills? Does it cost money?
qa-skills 是一套面向 AI 编程助手的开源测试技能，包含 13 个技能、共享知识库、模板和按需运行的 Python 辅助脚本。项目采用 MIT 许可证，无需 qa-skills 账号或订阅。使用时仍可能产生模型和工具费用；早期一轮主模型实验的 Token 用量约为对照组的 3.3 倍，实际用量取决于任务、模型和执行方式。
qa-skills is an open-source set of testing skills for AI coding agents. It includes 13 skills, a shared knowledge base, templates and optional Python helpers. The project is MIT-licensed and requires no qa-skills account or subscription. Model and tool fees may still apply. Token usage was about 3.3 times the control in one early main-model experiment; actual usage depends on the task, model and execution method.
哪些 AI 编程助手可以使用？Which AI coding agents can use it?
AI 助手需要能够发现技能并读取文件；执行测试还需要终端或浏览器工具。Claude Code、DeepSeek Harness（dsh）和 Codex 已有不同范围的验证记录，详见 兼容性说明。安装成功后，还应在实际任务中确认技能是否被读取、流程是否被遵循，以及产出是否符合要求。
Your agent must be able to discover skills and read files. Running tests also requires terminal or browser tools. Claude Code, DeepSeek Harness (dsh) and Codex have been validated to different extents; see compatibility and limits. After installation, check whether the agent loads the skills, follows the workflow and produces suitable results on a real task.
生成的用例可以直接执行吗？Can I run the generated cases as-is?
不能仅凭生成结果就认定用例可执行。qa-skills 要求写清前置条件、操作步骤、判定标准与异步等待时限；执行前仍需确认环境、账号和操作入口。历史对照实验中，用例规格符合度从 26% 提升到 98%，衡量的是用例是否符合格式与内容要求，不是测试执行通过率，也不代表所有模型都能达到同样结果。
Generated output still needs checking. qa-skills requires explicit preconditions, steps, pass criteria and time limits for asynchronous behavior. Confirm the environment, accounts and entry points before running a case. A historical comparison found case-spec compliance increased from 26% to 98%. This measures compliance with case format and content requirements, not test execution success, and is not a guarantee across models.
安装后，怎么开始测试？How do I start after installation?
先确认 AI 助手已读取所需技能，再提供需求材料、仓库路径，以及可用的测试环境和账号。可以说“帮我测试这个需求”，也可以只要求设计用例、评审用例或制定回归清单。缺少材料时应先补充或澄清；遇到需求歧义、执行方式、缺陷定性和预算等关键决策时，由你确认后再继续。
Confirm that the agent has loaded the relevant skill, then provide the requirements, repository path and available test environment and accounts. Ask it to test the requirement, or request a specific task such as case design, review or a regression checklist. Supply missing inputs or clarify them first. The workflow calls for your confirmation on ambiguous requirements, execution methods, defect classification and budget limits.
代码和测试数据会被上传吗？Will my code and test data be uploaded?
qa-skills 不内置遥测或托管服务，测试产物与 .qa/ 项目知识库保存在项目目录中。但 AI 助手、模型服务商和工具可能会处理你提供的代码与数据，测试脚本也可能访问配置的被测系统。使用前应分别确认这些服务和工具的数据处理规则。
qa-skills has no built-in telemetry or hosted service. Test outputs and the .qa/ project knowledge base are saved in your project directory. Your AI agent, model provider and tools may still process the code and data you share, and test scripts may contact the configured application. Check the data handling policies of each service and tool you use.
支持英文吗？Does it support English?
官网和 README 提供中英文版本。13 个技能中，12 个的简短描述为双语，bug-analysis 的简短描述及所有技能的指令正文仍为中文。英文任务的实际效果取决于 AI 助手和模型，需要在具体任务中验证。可到 Discussions 反馈英文使用场景和遇到的问题。
The website and README are available in Chinese and English. Twelve of the 13 skills have bilingual short descriptions; bug-analysis has a Chinese description, and all skill instruction bodies are currently in Chinese. Results with English tasks depend on the agent and model and need task-level validation. Share your use cases and issues in Discussions.

选择适合你的安装方式Choose an installation method

已安装 Node.js？运行下面的命令，再按提示选择 AI 编程助手和安装范围。保留 --skill '*'，以安装全部 13 个技能及 core 共享知识库：

With Node.js installed, run the command below and select your coding agent and installation scope when prompted. Keep --skill '*' to install all 13 skills and the core shared knowledge base:

$ npx skills add fishzjp/qa-skills --skill '*'

不使用 Node.js？克隆 GitHub 仓库并运行交互安装脚本，或按 README 手动复制文件：

Without Node.js, clone the GitHub repository and run the interactive installer, or follow the README to copy the files manually:

$ git clone https://github.com/fishzjp/qa-skills.git
$ cd qa-skills && ./install.sh

使用 DeepSeek Harness（dsh）时，克隆后执行 ./install.sh --target ~/.dsh/skills。升级时 git pull 后重跑同一命令。已有旧插件请先通过 dsh 插件管理器移除，避免重复装载。

Using DeepSeek Harness (dsh)? After cloning, run ./install.sh --target ~/.dsh/skills. To upgrade, run git pull and repeat the command. Remove any old plugin with the dsh plugin manager first to avoid duplicate loading.

请保留 core/ 共享知识库。上面的全量安装命令会一并安装；如果手动复制文件，也需要同时复制 core/，否则技能无法读取依赖文档。
