# flaky 治理手册（flaky-playbook）

> 本文件是 `test-reliability` 的工程约定细节层：判定树、证据表、修复模式库、健康度指标定义。
> 规范同源声明：第 2 节判定纪律与 `automated-e2e-testing` 工程约定（playwright-conventions §11）、
> `../core/triage.md` D 类、`../core/pipeline-integration.md` 回流纪律**规则一致**——各文件按
> 所在层展开，修改判定语义时须同步核对四处（单一事实源是"语义"，不是某一个文件）。

## 1. 复跑矩阵（根因归因的证据面）

对已定性 flaky 的用例，按需执行下列取证动作（每格记"通过/失败/未执行"）：

| 取证动作 | 回答的问题 |
|---|---|
| M1 原样重跑（同环境同顺序立即重跑） | 失败是否间歇（定性 first-run-flaky 的依据） |
| M2 隔离重跑（单跑该条） | 是否测试间依赖/共享状态（S2） |
| M3 干净环境重跑（新容器/新目录/新账号） | 是否环境残留或依赖抖动（S3） |
| M4 带序重跑（按原顺序连跑邻居 N 次） | 是否顺序敏感（S2）或资源竞态（S4） |
| M5 关并行重跑（workers=1） | 是否并发竞态（S4） |
| M6 时段复跑（隔天/错峰再跑） | 是否环境时段性（发布窗口/容量，S3） |

取证成本纪律：按判定树需要选跑，不要求全矩阵；每条 flaky 至少 2 项证据才允许定根因类，
只有 1 项证据时根因类标"暂定"并在报告中显式声明。

## 2. 判定树

```text
首跑失败
├─ 原样重跑(M1) 失败复现 → 非间歇 → 走执行 skill 单条流程（真失败候选，triage A 类入口）
└─ 原样重跑(M1) 通过 → 初判 first-run-flaky（不算稳定通过）
   ├─ 非平稳复核（§2.5，初判后、归因前强制执行）
   │   └─ 命中任一信号 → 翻转为真失败候选，上抛（不得按噪声隔离）
   ├─ 隔离重跑(M2) 失败/间歇
   │   ├─ 带序重跑(M4) 复现失败 → S2 共享状态/顺序依赖
   │   └─ 复现稳定失败但间歇 → S1 时序等待（查异步/轮询/动画窗口）
   ├─ 隔离重跑(M2) 稳定通过
   │   ├─ 关并行(M5) 后稳定 → S4 并发资源竞态
   │   ├─ 干净环境(M3) 后稳定 → S3 环境残留
   │   └─ 时段复跑(M6) 聚集失败 → S3 第三方/发布窗口
   └─ 全部通过且无法复现 → 证据不足：标"未知"，挂 M6 时段复跑观察，禁止硬编根因
```

### 2.5 非平稳信号复核（flaky 初判的强制翻转检查）

"重跑通过"只证明失败是间歇的，**不证明失败是良性的**。间歇失败背后可以藏着真缺陷
（性能回归、资源泄漏、渐坏依赖）——它们通过偶发超时/偶发错误表现为 flaky。
定性 first-run-flaky 之后、归因与隔离之前，必须核对三个非平稳信号：

| 信号 | 判据 | 含义 |
|---|---|---|
| **N1 失败率趋势** | 失败率随时间爬升或单调变化（对比历史窗口） | 噪声是平稳的；趋势性失败 = 系统在渐坏，疑性能/容量回归 |
| **N2 外部变更相关** | 失败起始时间与一次外部变更（发布、限流/配额策略、依赖升级）吻合 | 行为改变的因果在变更里，不是抖动 |
| **N3 阈值穿越** | 失败采样的关键指标（延迟/耗时/内存）已逼近或超过断言阈值 | 测试在正确报警，重跑通过只是踩线侥幸 |

- 命中任一信号 → **翻转为真失败候选**：按执行 skill 单条流程/triage A 类入口上抛，
  附趋势证据；**不得按噪声隔离**，也不得用调参（超时/重试）消化
- 三信号全不命中 → 维持 flaky 初判，继续判定树归因
- 证据不足无法核对（无历史窗口/无指标数据）→ 如实标注"非平稳复核不可执行"，处置降级为
  隔离 + 观察清单，禁止直接判噪声放行

> 设计动机：真缺陷穿着 flaky 外衣（间歇性性能回归）是测试套件里最危险的潜伏形态——
> 它既逃过失败告警（重跑会绿），又逃过隔离审查（被判为噪声）。本节是判定树的强制闸门。


## 3. 四分类证据表

| 类 | 典型证据 | 常见来源 |
|---|---|---|
| **S1 时序与等待不足** | 隔离重跑仍间歇；trace 显示断言先于状态就绪；网络/动画竞态窗口 | 异步渲染、轮询、懒加载、事件去抖 |
| **S2 共享状态与测试间依赖** | 隔离重跑稳定通过；带序重跑失败；数据残留（上条用例创建的资源未清理） | 全局单例、共享数据库、执行顺序假设 |
| **S3 环境与第三方抖动** | 干净环境重跑消失；失败聚集特定时段（发布日/备份窗口）；依赖服务超时日志 | 依赖服务、证书/账号过期、容量、CDN |
| **S4 并发与资源竞态** | 关并行后消失；端口/临时文件/唯一键冲突日志 | 并行 workers、共享端口、固定路径文件 |

## 4. 修复模式库

### 4.0 修复验证纪律

修复后按原复跑矩阵复验：M1 连续 ≥10 次通过（或 M4 带序 ≥5 轮）方可关案；
复验不通过 = 修复无效，回到判定树重新归因。**重试绿不算复验通过。**

### 4.1 S1 模式

- 等待降级阶梯：固定等待 → 目标态显式等待（元素/网络/URL 断言）→ 轮询断言（`expect.poll`）
- 禁止：`sleep` 加大、全局 timeout 调大、去掉断言
- 长连接/轮询页面：显式声明"页面永不空闲"策略，禁用 networkidle（同源 e2e 提问纪律）

### 4.2 S2 模式

- 测试数据工厂：每用例自建数据 + 自清理（afterEach）+ 唯一命名（前缀+时间戳）
- 顺序解耦：任何用例不得假设其他用例已运行/未运行
- 共享资源：数据库每用例事务回滚或独立 schema

### 4.3 S3 模式

- 环境断言前置：套件起跑先探活依赖，不健康即快速失败并标注"环境事件"（不污染用例统计）
- 错峰：避开发布窗口/备份窗口（M6 证据）；证书/账号过期进巡检
- 依赖边界：不稳定第三方依赖用契约测试替代端到端真打

### 4.4 S4 模式

- 资源独占：端口/文件路径/外部键全部参数化隔离
- 并行前提逐项核对：自建数据、自清理、唯一命名（同源 e2e 工程约定第 11 节）
- 必要时全局串行化该套件，并把并行化列为技术债

## 5. 套件健康度指标（机读格式）

挂靠 `../core/report-template.md` 机读摘要段，字段（yaml fenced，键名固定）：

```yaml
suite_health:
  total_cases: 0          # 参与统计的用例数
  clean_passes: 0         # 首次执行即通过
  retry_passes: 0         # 首次失败、重试通过（≠修复）
  quarantined_count: 0    # 隔离中（fixme/quarantine），不计入通过率分母
  flaky_rate: 0.00        # 期间定性 flaky 条目数 / total_cases，两位小数
  repeat_fail_count: 0    # 跨轮 ≥3 轮未修的 flaky 条目数（升级线）
  window: "14d"           # 统计窗口
```

- 门禁证据语义：任何把套件结果当发布证据的场合，`clean_passes`/`retry_passes`/
  `quarantined_count` 三项必须齐备且分开陈述；缺任一项 = 证据不合规
- `repeat_fail_count > 0` 时必须附升级动作（排期/上抛），不得只报数字
- 趋势要求：与上一窗口对比，`flaky_rate` 上升必须给归因假设与取证计划

## 6. 沉淀判定（交接 qa-memory）

值得写入 `.qa/` flaky-tests 主题的发现：环境时段性规律（M6 证据成立）、依赖抖动模式、
已验证有效的修复配方。条目必须携带复跑矩阵证据（处置段固定段落要求同源
qa-memory entry-schemas：症状/根因/处置，处置段含噪声 vs 真实失败判定方法）。
投毒防线：失实的"噪声可重试"条目会放行真实缺陷——证据不足的判定不得沉淀。
