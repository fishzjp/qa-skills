# judge 校准手册（judge-calibration）

> **路径口径**：本文档内 `../core/...` 等相对路径按消费方 SKILL.md 所在目录（`skills/ai-system-testing/`）解析书写，不是相对本文件。

> `ai-system-testing` 工作流四的细节层：怎么发现 judge 不可信。κ 概念的降维版——
> 本手册不要求计算完整 κ 系数，只要求建立"judge 可信度抽检"的最低纪律。
> 同源声明：证据分级 = `../core/evidence.md`；诚实披露条款 = SKILL.md 头部。

## 1. 最低校准纪律（任何 judge 上岗前）

1. **锚点集**：从评测集中取 ≥20 条，人工预先判定通过/失败（含明显好、明显坏、边界各若干）
2. **盲评**：judge 对锚点集评分，**不见人工判定**；人工判定先于 judge 落盘
3. **一致率门槛**：judge 与人工一致率 ≥0.8 方可上岗；0.6–0.8 限用于粗筛（低风险结论）；<0.6 不可信
4. **抽检频率**：换 judge / 换模型 / 换 prompt 任何一项变更 → 重校准；同配置连续使用 → 每 200 次判定抽检一次

## 2. judge 不可信的信号（任一命中即回炉）

| 信号 | 表现 | 对策 |
|---|---|---|
| **锚点失分** | 明显好样本被判失败（或反向） | 判分指令与 rubric 冲突，重写 judge 指令；仍失分→换 judge |
| **宽容偏置** | 差样本普遍得分偏高（"看起来还行"式通过） | 判分点改为可机械核对项；提高 judge 指令的具体性 |
| **严厉偏置** | 好样本普遍失分 | 同上，方向相反 |
| **位置依赖** | 同内容不同顺序评分不同 | 固化产出顺序；多次采样取多数 |
| **自我偏好** | judge 对某族模型生成的内容系统性打高分 | 披露族别关系；换异族 judge 或人工兜底 |
| **证据空洞** | 判"通过/失败"但给不出引用原文的证据 | 判分点改为要求引用定位；无证据的判定视为无效 |

## 3. 判分记录纪律

- 每次 judge 判定落盘：judge 模型版本 + prompt 版本 + 逐点 covered 与 evidence 引用
- 多次采样表决（JUDGE_SAMPLES≥3）时记录分歧项——分歧率异常升高 = judge 或产物在漂移
- **judge 结论必须挂证据链**：判"失败"须引用产出原文位置；无证据判定按无效处理（不计入分母时显式声明）

## 4. 与报告的关系

《AI 评测报告》的方差披露节必须包含：judge 身份、最近一次校准一致率与日期、锚点集大小。
未做校准的 judge 结论只能标注为"未校准观察"，不得作为验收证据。
