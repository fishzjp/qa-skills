# 评测设计模式库（eval-design-patterns）

> **路径口径**：本文档内 `../core/...` 等相对路径按消费方 SKILL.md 所在目录（`skills/ai-system-testing/`）解析书写，不是相对本文件。

> `ai-system-testing` 工作流一/二的细节层。判分点模板、断言模式库、样本设计清单。
> 同源声明：判分点可判定性标准 = `../core/executability.md`；证据分级 = `../core/evidence.md`。

## 1. 判分点（rubric）模板

每个判分点四要素（缺一即不可判定，回炉）：

```text
P{id}: {判定对象} + {判定标准} + {判定方式: 硬断言|人工|judge} + {优先级}
```

- 反例："摘要质量良好"——对象模糊、标准不可核对
- 正例："P3: 摘要包含输入中的全部 3 个金额字段（150/2300/78.5 元），且未出现输入中不存在的金额——硬断言（字符串包含 + 数值抽取比对）"

## 2. 样本设计清单（评测集必须覆盖）

| 样本类 | 目的 | 数量建议 |
|---|---|---|
| 顺样本（典型输入） | 基线能力判定 | ≥5 |
| 边界样本（最长/最短输入、极端值、多语言混排） | 鲁棒性 | ≥3 |
| 反样本（应拒答/应为空/应降级） | 过度生成面 | ≥2 |
| 注入样本（指令劫持/泄露尝试） | 安全面（交工作流五） | ≥2 |
| 历史回归样本（曾出问题的 case 脱敏） | 防复发 | 全部 |

## 3. 断言模式库（按确定性降序）

| # | 模式 | 适用 | 判定方式 |
|---|---|---|---|
| A1 | 结构断言 | 输出为 JSON/固定格式 | schema/字段存在性硬断言 |
| A2 | 关键字段精确 | 金额/ID/日期/枚举 | 逐字相等 |
| A3 | 内容包含 | 关键事实/结论/免责声明 | 关键词/语义槽位包含 |
| A4 | 禁止项断言 | 无编造/无泄露/无越权 | 输出中不得出现（负向硬断言） |
| A5 | 阈值断言 | 数值判分（相似度/命中率/覆盖率） | ≥阈值；阈值须注明来源（业务约定或历史分布 P90） |
| A6 | 多数投票 | 应当稳定的行为 | n≥3 采样按多数；记录采样参数 |
| A7 | judge 评审 | 长文本语义质量 | 校准过的 judge + 逐点证据；单 judge 结论须挂证据链 |
| A8 | 人工评审 | A7 不可信时的兜底 | 抽样；双人复核分歧项 |

组合原则：一条评测样本通常 = A1/A2 打底（结构+关键字段）+ A3/A5（内容与数值）+ 可选 A7（整体质量分）。
**逐字断言自然语言长文本 = 反模式**（唯一例外：引用类输出要求原文可定位，用"包含"而非"全等"）。

## 4. 评测集自身的质量闸

- 锚点对照：预埋已知好样本（应得高分）与坏样本（应得低分）——judge/人工评分分不开 = rubric 无效回炉
- 判分点独立性：一个判分点的通过不得依赖另一个判分点先通过（耦合点合并）
- 难度标定：评测集对已知好模型应得高分、对弱模型/坏 prompt 应得低分（区分度）——全对或全错 = 无区分度

## 5. 报告挂靠

评测集与 rubric 全文进《AI 评测报告》附录；正文引用判分点 id。方差披露节必备：样本量、每判分点通过率、多次运行的区间、已知盲区（未覆盖的边界）。**优先级分级 + 验收线显式声明**（如"P0 全过为验收底线"）。**评测集样本锚定四元组**：prompt/模型版本/温度/语料版本——缺任一，换版本后样本即失效（不可复现 = 无效评测）。
