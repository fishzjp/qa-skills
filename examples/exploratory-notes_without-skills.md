# 探索笔记_文档分享与权限.md

## Charter

- **目标**：检验在线文档系统「分享与权限」功能在文档分享后是否存在权限泄漏。
- **范围**：Web 端分享弹窗的链接范围（仅邀请者、组织内、互联网、关闭分享）、邀请成员、评论通知、并发编辑、版本历史、导出、权限变更缓存、API 访问控制。
- **账号与文档**：owner（doc-owner@lab）、user-a@lab、user-b@lab；文档 `季度复盘.docx` 归 owner 所有。
- **停点**：风险清单满 10 条或时间盒 2 小时到。

## 系统理解

基于本轮探索，对「分享与权限」功能域的理解如下：

1. **分享链接范围**：弹窗提供四种链接范围——仅邀请者、组织内获得链接者、互联网上获得链接者、关闭分享。默认选中「组织内」。
2. **权限变更缓存**：权限变更（如范围从互联网改回仅邀请者）后，旧权限仍持续约 5–6 分钟；移出组织后，已打开的标签页在约 10 分钟内仍可编辑，刷新后失效。表明存在客户端/服务端缓存窗口。
3. **评论通知越权**：评论者 @ 其他用户（即使该用户不在分享对象中），被 @ 用户可通过通知链接直接查看文档全文。
4. **并发编辑**：多人同时编辑同一文档时，修改可正常合并，无丢字。
5. **版本历史**：支持最近 50 个版本，回滚可撤销。
6. **导出**：PDF 导出仅含正文，不含批注（有意设计）。
7. **标题**：支持 emoji 和长标题（60 字符），分享卡片截断正常。
8. **UI 风格**：深色模式下分享弹窗说明文字颜色偏浅（已另开议题，与权限无关）。
9. **审计日志**：猜测每次链接范围变更会写审计日志，但未找到查看入口，未验证。

## 测试想法

1. **缓存窗口期验证**：
   - 针对每种链接范围变更（组织内→仅邀请者、关闭分享、移出组织等），测试旧权限的有效时长，并确认是否与当前观察到的一致。
   - 测试不同操作（如删除链接、关闭分享）后窗口期是否相同。
   - 测试浏览器/客户端完全关闭后重开是否仍受缓存影响。

2. **@通知权限泄露**：
   - 构造场景：任意评论者 @ 不在分享列表中的用户，检查被 @ 用户是否始终能通过通知访问文档。
   - 测试不同权限角色（查看者、评论者、编辑者）@ 用户时的效果。
   - 测试被 @ 用户是否拥有与评论者相同的权限（如编辑、评论、分享）。

3. **组织成员变更后权限时效**：
   - 测试移出组织后，不同权限（查看、评论、编辑）的缓存窗口期是否一致。
   - 测试重新加入组织后权限恢复的时效。

4. **审计日志验证**：
   - 尝试通过 API 或后台入口查询审计日志，确认是否存在权限变更记录。
   - 若日志存在，测试记录内容是否完整（时间、操作者、变更前后范围）。

5. **并发编辑与权限冲突**：
   - 测试前端编辑冲突时权限模型是否仍正确（如降级权限后正在编辑的用户是否被强制退出）。

## 发现的 Bug

本轮探索未确认任何 Bug。观察到的异常现象（R1、R3、R4）已作为 Hypothesis 记录在风险清单中，待与系统 Owner 确认后移入 Bug 列表。

## 未解之谜

以下问题需向系统 Owner 澄清：

1. 权限变更（R1、R4）后的缓存窗口期是已知设计意图还是底层实现缺陷？是否有明确的设计文档？（观察来源：3、13）
2. 评论 @ 通知允许未分享用户访问文档（R3）是否为预期行为？若预期，是否应在分享设置中提供控制开关？（观察来源：5）
3. 移出组织后约 10 分钟的缓存窗口是否与前述 5–6 分钟窗口属于同一机制？为何时间不同？（观察来源：13）
4. 审计日志（R5）是否真的存在？若存在，如何查看？（观察来源：14）
5. 默认分享范围设置为「组织内」是否满足安全预期？是否有优化空间（如强制每次选择）？（观察来源：1）
