# 示例:同一个任务,Skill 开 / 关的产出对照

来自评测黄金集任务 `tcw-coupon-prd`(同一份 PRD:优惠券创建功能,含面额边界/有效期双模式/同商户名称唯一/发布状态流转等规则),**同模型、同 harness、唯一差异是否注入 qa-skills**。是完整真实产出,未做修饰。

| 文件 | 条件 |
|------|------|
| [test-cases_with-skills.md](./test-cases_with-skills.md) | **有 Skill**(test-case-writing 全部指令注入) |
| [test-cases_without-skills.md](./test-cases_without-skills.md) | **无 Skill**(仅"你是资深测试工程师"人设) |

## 拿两份文件对比什么

打开后先看**无 Skill 版**,注意这些地方:

- `TC-UI-001:访问优惠券创建页面,页面正常加载,无报错`——"正常"如何判定?报错看哪里?
- 环境信息"待提供"三个字打发了——执行者不知道**找谁拿什么**
- 大量用例堆在界面展示层,业务规则(如"已发布状态仅发放总量可调大")的验证入口和判定深度不足

再看**有 Skill 版**的同一块:

- 导读四件套齐了:角色表、环境与账号表(未知项写成 `TODO:向谁索取什么` 而不是"待提供")、术语表、图例
- 状态流转逐边有用例:TC-02-01~06 把"待发布 → 已发布"的编辑权限、拦截条件、发布后表现拆成可判定的一串用例
- 异步行为带判定时限:搜"判失败"能看到"到达结束时间后 1 小时内自动变为已结束,超过 1 小时未变判失败"——多久没变算失败写死了
- 附录物理隔离代码证据(可搜 `附录` 对比)

## 这些数字在评测里意味着什么

该任务在验证轮(run 20260820_1429_v2,3 采样)的实测:有效覆盖 On 99.6% vs Off 97.1%,可执行性 On 0.996——但**单任务不构成统计结论**,全套指标、置信区间与门判定见 [eval/results/LATEST.md](../eval/results/LATEST.md),方法学与诚实声明见 [DESIGN.md](../DESIGN.md) 第 10 节。
