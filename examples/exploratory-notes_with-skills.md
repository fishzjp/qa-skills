# 探索笔记：文档分享与权限

## Charter（本轮探索的使命）
- **目标**：弄清楚把一个文档分享出去之后，权限到底会不会漏
- **范围**：在线文档系统（Web 端）的「分享与权限」功能域
- **时长/停点**：2 小时时间盒，或风险清单满 10 条（本次时间盒先到）

## 系统理解（探索中修正）
- 分享弹窗提供四种链接范围：仅邀请者、组织内获得链接者、互联网上获得链接者、关闭分享；默认选中「组织内」。
- 不同链接范围控制文档的访问方式：仅邀请者需显式添加用户；组织内可通过链接直接访问；互联网上可通过链接直接访问；关闭分享后链接不可用。
- 链接范围变更后存在缓存窗口期：从“互联网上获得链接者”改为“仅邀请者”后，原链接约 5–6 分钟内仍可访问，之后被拒绝（截图 IMG_2043）。
- 评论者可通过 @ 功能邀请其他用户，被 @ 的用户即使不在分享列表中，也能通过评论通知直接访问文档全文。
- 文档 URL 中替换文档 ID 的权限控制有效：对可见文档可访问，对未见文档返回无权限页；API 接口行为与页面一致。
- 并发编辑支持冲突处理：两个用户同时编辑同一文档，修改内容未被覆盖，但可能被移动到其他段落（具体算法需进一步了解）。
- 版本历史面板保留最近 50 个版本，支持回滚，回滚后可撤销。
- 导出为 PDF 的文档不含批注内容（有意设计，开发群确认）。
- 文档标题支持 emoji 及长标题（60 字符）在分享卡片上正常截断。
- 深色模式下分享弹窗说明文字颜色偏浅（UI 问题，与权限无关）。
- 将用户移出组织后，该用户已打开的文档标签页不会立即被踢出，仍可继续编辑约 10 分钟，直到刷新才失效。

## 风险清单（每条带证据标注，预评级）

### R1：分享链接范围变更后，原有链接存在缓存窗口期，可能导致权限变更未立即生效
- **描述**：分享范围从“互联网上获得链接者”改为“仅邀请者”后，原链接约 5–6 分钟内仍可访问，之后才被拒绝。若此期间链接被恶意利用，可能造成信息泄露。
- **evidence**：E3（IMG_2043，截图）
- **Impact**：5（安全：权限泄露） × **Likelihood**：3（每次变更均可能触发） = **Score**：15 → **High**
- **confidence**：high
- **status**：hypothesis（未定性是否为预期设计）

### R2：通过评论通知可能绕过分享权限，导致未授权用户访问文档
- **描述**：评论者在文档中 @ 其他用户，被 @ 的用户即使不在分享对象列表中，也能通过通知链接直接查看文档全文，可能造成权限泄露。
- **evidence**：E3（观察到的实际运行结果，无截图）
- **Impact**：5（数据泄露） × **Likelihood**：4（评论者可轻易 @ 任意用户） = **Score**：20 → **Critical**
- **confidence**：medium（依赖观察者记录）
- **status**：hypothesis（需确认是否为预期行为）

### R3：用户移出组织后，已打开的标签页仍可编辑约 10 分钟，权限回收未立即生效
- **描述**：将用户移出组织后，该用户已打开的文档标签页未被踢出，仍可继续编辑约 10 分钟，直到刷新才失效。可能造成敏感文档泄露。
- **evidence**：E3（观察结果，无截图）
- **Impact**：5（安全：权限回收延迟） × **Likelihood**：3（管理员移出组织后，用户若不刷新可继续操作） = **Score**：15 → **High**
- **confidence**：medium
- **status**：hypothesis

### R4：关闭分享后可能也存在类似的缓存窗口期（未验证）
- **描述**：基于 R1 的观察，推断“关闭分享”操作后，已分享的链接可能仍有一段时间窗口可访问，导致权限失效。
- **evidence**：E0（用户推断，未验证）
- **Impact**：5（信息泄露） × **Likelihood**：2（需确认，可能较小） = **Score**：10 → **High**
- **confidence**：low
- **status**：hypothesis

### R5：链接范围变更操作是否记录审计日志未知，若缺失可能导致权限变更无法追溯
- **描述**：每次链接范围变更应记录审计日志以便追溯，但当前未找到查看入口，无法确认是否存在。
- **evidence**：E0（猜测，未验证）
- **Impact**：3（合规/审计缺失） × **Likelihood**：3（若未记录，则每次变更都不可追溯） = **Score**：9 → **Medium**
- **confidence**：low
- **status**：inference

## 测试想法（后续转化为正式用例的候选）
1. **验证关闭分享操作的缓存窗口期**：执行“关闭分享”后，立即用原链接访问，检查是否立即失效或存在时延（基于推断）。
2. **验证评论 @ 功能的权限范围**：以不同角色评论并进行 @，验证被 @ 用户是否始终能访问文档，以及是否受分享范围限制。
3. **验证组织成员移除后权限回收的边界**：测试移出组织后，用户正在编辑的文档是否自动保存、是否提示权限变更、编辑内容是否生效。
4. **验证审计日志的存在与内容**：通过开发者工具或 API 检查分享范围变更是否记录审计日志，日志包含哪些字段。
5. **验证导出格式（如 Word、HTML）是否包含批注**：确认其他导出格式与 PDF 行为一致。
6. **验证深色模式下分享弹窗的 UI 对比度**：提交 UI 问题，建议调整文字颜色。
7. **验证版本历史回滚后权限状态**：回滚后文档内容发生变化，分享权限是否保持不变。

## 发现的 Bug（现象 + 复现步骤 + 证据；未定性，标 Hypothesis）

### Bug H1：分享链接范围变更后，缓存窗口期导致权限未立即生效
- **现象**：将分享范围从“互联网上获得链接者”改为“仅邀请者”后，原链接在约 5 分钟内仍可访问，约 6 分钟后被拒绝。
- **复现步骤**：
  1. 以 owner 创建文档，设置分享范围为“互联网上获得链接者”。
  2. 以 user-a 打开该链接，确认能访问。
  3. owner 将分享范围改为“仅邀请者”。
  4. 立即切换回 user-a，刷新链接（或等待 5 分钟内），仍可访问。
  5. 等待约 6 分钟后，链接被拒绝。
- **证据**：E3（IMG_2043，截图）
- **status**：hypothesis

### Bug H2：评论通知可能绕过文档分享权限
- **现象**：评论者 @ user-b 后，user-b 能通过通知链接直接查看文档全文，即使 user-b 不在分享对象列表中。
- **复现步骤**：
  1. owner 创建文档，分享给 user-a（评论者权限）。
  2. user-a 在文档评论中 @ user-b。
  3. user-b 收到评论通知，点击通知链接，能够查看文档全文。
  4. 确认 user-b 原无访问权限。
- **证据**：E3（观察结果，无截图）
- **status**：hypothesis

### Bug H3：移出组织后，已打开标签页权限未立即回收
- **现象**：将 user-b 移出组织后，user-b 已打开的文档标签页仍可继续编辑约 10 分钟，刷新后才显示无权限。
- **复现步骤**：
  1. 以 organization 范围分享文档给 user-b。
  2. user-b 打开文档并开始编辑。
  3. 管理员将 user-b 移出组织。
  4. user-b 的标签页仍可编辑，约 10 分钟后刷新才失效。
- **证据**：E3（观察结果，无截图）
- **status**：hypothesis

## 未解之谜（需要用户/开发澄清的问题）

### Q1：缓存窗口期的设计意图
- **场景**：Bug 定性
- **来源**：观察记录第 3 条、第 13 条
- **具体问题**：分享链接范围变更（包括改为仅邀请者、关闭分享）以及移出组织后，权限变更存在一定的缓存延迟（约 5–10 分钟）。这是预期设计（如 CDN 缓存、Token 缓存）还是缺陷？如果是预期，缓存时长是多少？是否有配置参数？
- **影响**：影响风险评级和测试策略，若为设计需明确缓存时长，若为缺陷需要修复。

### Q2：评论 @ 功能是否应允许绕过分享权限
- **场景**：Bug 定性
- **来源**：观察记录第 5 条
- **具体问题**：评论者 @ 其他用户后，被 @ 的用户能通过通知直接访问文档全文，即使该用户不在分享对象列表中。这是预期行为（为方便协作，评论通知提供临时代理访问）还是权限漏洞？如果是预期，是否有其他限制（如仅限阅读、过期时间）？
- **影响**：涉及数据安全，需明确设计意图。

### Q3：审计日志是否存在及其访问方式
- **场景**：需求澄清
- **来源**：观察记录第 14 条
- **具体问题**：每次分享范围变更是否记录审计日志？如果记录，如何查看（界面入口、API）？日志包含哪些字段（操作人、时间、变更前后范围等）？
- **影响**：合规和追溯能力，影响测试范围。

### Q4：移出组织后，用户正在编辑的内容是否保存
- **场景**：需求澄清
- **来源**：观察记录第 13 条
- **具体问题**：用户被移出组织后，其正在编辑的文档内容是否会被自动保存？如果用户继续编辑并保存（在缓存窗口内），这些保存是否生效？如果用户刷新后失去权限，编辑的内容是否丢失？
- **影响**：数据一致性，需要明确用户和协作流程。

### Q5：深色模式分享弹窗文字颜色偏浅是否为 UI Bug
- **场景**：Bug 定性
- **来源**：观察记录第 12 条（IMG_2051）
- **具体问题**：深色模式下分享弹窗的说明文字颜色偏浅，是否属于 UI 缺陷？是否需要修复？
- **影响**：用户体验，但非功能问题，可酌情处理。
