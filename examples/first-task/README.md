# 第一次使用：从需求到可审查的测试用例

[English](./README.en.md)

用一份虚构的会议室预约需求，体验需求澄清、策略、用例与独立审查。无需生产账号或测试服务；本练习只做文档任务，**不会证明测试代码已经执行或模型整体增益**。

## 1. 安装并确认装载

按 [README](../../README.md#快速开始) 安装全部单元及 core。克隆本仓库后可检查实际安装目录：

```bash
python3 scripts/verify_install.py ~/.agents/skills
```

目录以宿主实际读取位置为准。文件校验通过后，在宿主装载记录中确认 skill 和 core 文件确实被读取。

## 2. 提交需求

在本仓库启动 Agent，复制以下请求。也可将本目录复制到独立练习项目；将路径改为该项目中的实际路径。

```text
请使用 requirement-analysis 分析 examples/first-task/requirement.md。
这是虚构产品，当前没有代码、页面或测试服务。只进行文档设计，不执行网络请求。
将产物写到 .qa-practice/，先列出需要我裁决的问题并等待答复。
不要虚构入口、账号、定位器或已经执行的结果。
```

练习可采用以下**由你确认后才生效**的假设继续：采用 UTC 服务端时间；已开始预约不允许取消；页面入口、账号与提示文案保持未确认。请将裁决及尚未解决的问题记入需求模型。

## 3. 分阶段继续

```text
以上假设我已确认。请将裁决写入需求模型，再使用 test-strategy 制定策略；
然后使用 test-case-writing 编写用例，使用 test-case-review 独立审查。
所有产物写入 .qa-practice/。缺少运行环境的步骤明确标为待补充或阻塞，
不要把文档评审通过写成测试执行通过。
```

预期会产生需求模型、测试策略、markmap 用例、Schema 及审查记录；具体命名遵循各 skill。若宿主不能调度阶段 skill，可逐条提交阶段请求并提供上一阶段文件路径。

## 4. 人工验收

- 30/120 分钟边界、无效时间顺序、相邻不重叠和重叠预约都有明确判定。
- 普通用户/管理员、自己的/他人的预约有权限区分。
- 同时冲突预约有“最多一个成功”的判定；未执行时不填成功率。
- 时区和取消规则引用你的裁决；未知入口与账号保留未确认项。
- 用例具备前置、步骤、预期；缺少执行条件的条目如实标记。
- 审查包含具体缺口或修改依据，不能仅写“检查通过”。

这是一份学习检查清单，不是维护者评测 GT 或固定得分标准。若产物不满足要求，保留输入、实际装载路径与失败片段，按 [支持指南](../../.github/SUPPORT.md) 反馈。

练习产物 `.qa-practice/` 已在本仓库忽略；不要提交生成结果、账号或业务数据。
